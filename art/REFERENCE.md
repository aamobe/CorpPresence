## 证据范围与口径

来源是当时本地游戏的`Probably Stolen_Data/resources.assets`，用AssetStudio CLI提取Sprite PNG和部分Sprite／Texture2D元数据；读取同版`Managed/Assembly-CSharp.dll`的IL核对显示逻辑。原始输入由下列哈希标识，不依赖作者机器盘符。

- resources.assets SHA256：`97610CEA54D8C36746FBBB05F928B9A28A776CC90D0EC586B14B360B37444B4B`
- Assembly-CSharp.dll SHA256：`6398D44AA1675E1F02B63BC668868F970E0F5D3AE5A50F2ACED8D06CA084E3B5`
- 按名称抽样得到 **137 张 PNG**，包含状态图、零件及 UI 图标，不是137种独立商品，也不是全游戏普查。
- 以 Alpha ≥128 定义“主体像素”用于比较；110 张有主体，27 张全部低于阈值。这27张只保留尺寸/元数据证据，不用于推导颜色预算；可能涉及资源用途、导出或显示处理，本次未确定原因。
- “颜色数”指主体像素的不同 RGB 数，不计算低 Alpha 背景。另存完整 Alpha 直方图。RGBA颜色数、RGB颜色数、调色板预算三者不同。
- 统计与来源：`evidence/sprite-metrics.csv`、`evidence/sprite-metrics.json`；每张记录 SHA256。原图在 `evidence/native/Sprite/`，结构元数据在 `evidence/metadata/`。
- `evidence/native-contact-sheet.png` 为4倍最近邻诊断图，空白的 revolver 样本是低 Alpha 导出例外，不代表原版游戏没有贴图。

以下把**实测**、**代码证据**和**制作建议**分开。Alpha阈值和建议不是原版作者的官方规范。

## 调色板与材质

原版鼠笼主体的8个RGB：

`#292234 #373541 #3D823F #44464C #53585B #5F6868 #7AB053 #88948A`

这是鼠笼材质参考，不是全游戏唯一调色板。其主体像素主要分布如下：

| 色值 | 像素数 | 用途观察 |
|---|---:|---|
| #5F6868 | 1232 | 顶盖与主要外壳的大色块 |
| #292234 | 526 | 深轮廓、孔洞和阴影 |
| #44464C | 350 | 外壳较暗面 |
| #53585B | 284 | 中间层次 |
| #373541 | 123 | 深灰结构 |

仅最大一块颜色就占主体约46.1%。机器的质感来自连续的面、阴影和结构，不能用随机杂色点补“金属细节”。

鼠类也使用有限颜色，但并非所有阶段颜色完全相同：rat_s_m／rat_m_m 是5色，rat_xxl_f也是5色但主色偏灰。不同生长阶段/性别要按相应参考制作，不能把母鼠当成公鼠的纯缩放版本。

当前跑轮导入图的16色预算虽然较少，但灰白亮色 `#B2B7C0`、亮绿 `#B3DB62` 与原版鼠笼并不相同。**限色数不等于调色板匹配**；同色相也不等于亮度层次和使用面积匹配。

## 像素密度与主体比例

原版鼠笼主体包围盒（Alpha≥128，含端点）为 `(0,1)-(63,46)`；画布64×48，几乎用满宽度，外侧仍有透明边角。当前生成图导入后主体约2327像素，原版为2672像素。两者画布相同但结构、留白和主体面积不同，视觉体量就会变化。

保留完整画布，而不是自动裁剪每个状态的主体再重新铺满。为改装件留出空间时，优先调整局部结构；缩小整笼会同时缩细把手、孔洞和格栅。

为了辅助诊断，工具还统计“上下左右都没有同RGB主体邻居”的像素：鼠笼74/2672≈2.8%，炉子21/2024≈1.0%，小肉块26/140≈18.6%。这只是一项结构指标：单像素灯、眼睛和肉纹都有用途，**不能制定所有素材孤立像素比例必须低于某值**。

## 原版渲染与MOD路径

已核对的 Sprite 元数据（鼠笼、老鼠、炉子、电池、灌装机等）均为 PPU=100、pivot=(0.5,0.5)。这只代表本次抽样；导入其他类型时继续检查。

5个物品图集 `items_husbandry/items_medical/items_sec/items_tool/items_tool2`：512×512、RGBA32、FilterMode=0（Point）、m_MipCount=10；底层 image_data 长度1398100字节，与512²至1²的RGBA32 mip链相符。工具同时输出旧字段 m_MipMap=false，**不可只依据这个旧字段断言没有 mip**。UI的 networkIcons 则682×493、m_MipCount=1、Point。

游戏IL确认：

- `UISettings::.ctor` 默认 gridSize=16；运行时该字段仍可能由配置/资源改变。
- `GameItemElement` 使用 `Image.SetNativeSize()`，并按网格处理物品显示。
- `GameItem.BuildShapeFromSprite` 从 `sprite.rect` 和 gridSize 算格数，并读取 `mipLevel=(int)Math.Sqrt(gridSize)` 的 Alpha。默认16时是第4级（基础级为0）。
- 公司MOD目前 `Tex.New/Art` 使用无mipmap的Texture2D和Point；`Goods` 提供独立的占格构造，支持明确的Shape。不能将此设置未经分析直接复制到依赖原版mip占格的路径。

完整相关类IL仅保留在作者本地，GitHub不附转储；可用[只读检查工具](tools/README.md)对自己的同版游戏重核。本次没有重建所有Canvas、材质、相机和显示器设置，因此最终屏幕缩放仍须游戏内验证。

## 本次未作的推断

- 不把低Alpha导出样本解释为游戏内不可见或资源损坏。
- 不把137张抽样扩展为全游戏风格统计。
- 不从原版最终PNG反推作者一定使用了哪种绘图软件或制作流程。
- 不保证仅修改PPU、筛选方式或颜色上限就能恢复原版质感。
- 不把本文的制作建议称作原版官方规范。
