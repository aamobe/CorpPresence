# 像素尺寸、缩放与游戏导入

> 当前执行规则（2026-11-13）—新精灵直接生成独立文件并原样保存，按同目录 AGENTS.md 的“直接生成精灵”验收。禁止预览稿或高清合图再缩小交付。以下转换方法仅限用户明确授权的既有贴图编辑任务。

> 原生 PNG 是最终交付物；用户对照与必要像素诊断可用同倍率原图和整数最近邻放大图，单独保存，不作为运行时素材。缩小后的原生图仍须执行防杂色检查。

本文是素材规范的缩放详则。先区分源图、逻辑像素和屏幕像素，再选择工具参数。

## 1. 五种尺寸不能混用

| 名称 | 鼠笼示例 | 决定什么 |
|---|---|---|
| 原生逻辑画布 | 64×48 | 最终像素设计空间，4×3个16像素格 |
| 主体包围盒 | 原版 `(0,1)-(63,46)` | 画布内物体实际体量及留白，不应逐帧自动裁剪 |
| PNG纹理尺寸 | 推荐64×48；特殊HD路径可能128×96 | 采样数与内存，不自动决定占格 |
| Unity显示单位 | 由rect、PPU、Canvas参考PPU及布局决定 | 同一PNG为何在游戏里显示大小不同 |
| 屏幕像素尺寸 | 随游戏UI缩放、分辨率及父级变换改变 | 是否整数像素映射、是否出现线宽跳动 |

**画布比例相同只是第一项条件。** 两张64×48图可能有不同的主体留白、轮廓宽度、投影角度、亮部面积和像素密度，质感仍会相差很大。

## 2. 首选流程：直接在最终网格上完成

1. 查参考的PNG和Sprite rect，确认原生尺寸与物品占格。
2. 创建同尺寸母版，保留原版改装任务中的锁定像素区。
3. 在1×检查轮廓和识别度；在4×最近邻检查线宽、连接与重复图案。
4. 添加一处细节后回到1×确认它仍可读。用1像素亮点表现灯可以成立；大图里的窄线不能假定缩小后仍成立。
5. 生成状态差分时复制母版、使用变化掩膜；公共区域逐像素相同。
6. 用原生PNG导入。放大预览单独保存，不作为运行时资源。

生成尺寸不符时记录偏差并重新生成；持续不符则说明工具限制，转换或重绘须有用户另行授权。

## 3. 放大：整数复制可逆，插值会改图

对于原生图 `I(x,y)`，整数放大n倍应满足：

```text
J(nx+i, ny+j) = I(x,y),  0 ≤ i,j < n
```

每个原始像素变成同色n×n方块。64×48→128×96、256×192、1024×768可分别是2×、4×、16×无损预览，**前提是确实采用逐像素复制**。

操作要求：最近邻/Point、关闭平滑、整数输出尺寸、对齐像素原点；使用System.Drawing绘制预览时指定NearestNeighbor与正确像素中心（本项目诊断工具用PixelOffsetMode.Half）。验收由像素比较确认，不能只看参数名称。

双线性、双三次、Lanczos、锐化、超分辨率会混色或改变边缘，不用于制作忠实放大预览。它们在别的图像任务中有用途，但不能称为像素保持操作。

### 非整数屏幕缩放

64×48显示为96×72是1.5×。使用Point时不会混色，但源像素只能分配为不均匀的1或2个屏幕像素，重复格栅可能看起来粗细不一。平移或尺寸变化还会改变分配位置，出现跳动。

因此“没有发糊”不等于“像素结构稳定”。发现问题要记录Canvas实际scaleFactor、父级scale、位置和UI设置，不能一律改贴图或强行改游戏全局UI缩放。至少比较同一截图中原版和MOD物品。

## 4. 缩小：只有严格整数复制图能直接还原

### A. 可证明的整数放大母版

高分图的每个n×n块内部RGBA完全一致，块原点与裁切位置明确，且宽高都是原生尺寸的同一n倍。这时取块中任一点还原均应一致，并与原生母版逐像素比较为零差异。

检查不是“图像看起来有像素块”，而是完整块内比较。原点不确定时先找对齐；不要随便裁去空边再采样。

### B. 普通大图或生成式像素风图

通常不满足上述条件：有细碎纹理、平滑边缘、大小不一的假像素块，格栅周期也不一定是n的整数倍。最近邻降采样只抽取一个点，会把其余信息丢弃；限色只改变取到的颜色，无法恢复未取到的线。

面积/箱式平均可以减少某些取样跳变，但会产生混色，之后限色仍可能断线；多数色块法会忽略细线；锐化会引入额外亮暗边。这些都只是辅助初稿方法，最终必须按原生网格修整并检查关键结构。

**严禁将“高分生图→单点缩小→最近色量化”作为自动验收通过的生产路径。** 若暂用作草稿，应明确标记未通过原生像素验收。

### C. 宽高比例不一致

```text
sx = 源裁切宽 / 目标宽
sy = 源裁切高 / 目标高
```

等比缩放需sx=sy。1024×1024直接变64×48，sx=16、sy≈21.33，会压扁物体。应先确定完整画布和留白，再决定裁切或补边；不能把“塞进画布”当等比缩放。两张差分必须共用同一裁切框与原点。

### D. 从原生图变成另一种尺寸

64×48→32×24即使是整除也会丢掉一半线性采样；一像素格栅可能完全消失。需要适配后的新像素设计。32×24还不是16像素库存网格的常规画布，须重新确认用途/占格。

原版鼠类从32×16到48×16再到64×32，形状、比例、细节会随阶段改变。这些样本不能当作同一张图的等比放大序列。

### 缩小后的防杂色步骤

1. 缩小前标出大平面（顶盖、底座、机壳、瓶身）与结构细节（边缘、格栅、铆钉、灯、文字标记）。为每个平面指定主色和必要的阴影／亮边，避免混用其他材质的调色板。
2. 缩小结果先视为草稿。在1×和4×最近邻下逐个平面检查：近似色是否随机交错、阴影是否碎成斑块、细纹是否变成孤立亮点。面积平均也会混色；最近邻、限色数量和颜色距离算法都不能代替这一步。
3. 将无结构作用的杂点在原生网格上合并回该平面的连续主色；明暗只按真实的折面、边缘或有意设计的材质分区保留。逐项修整格栅间距、固定片和轮圈等结构，不对整图盲目模糊、抹平或进一步减少颜色。
4. 复查被保留的单像素点是否有明确用途，例如指示灯、螺钉、眼睛或必要转角；有机物纹理不能按金属平面处理。没有用途的孤立点不因“看起来像磨损”自动豁免。
5. 同一设备的状态差分共享清理后的基准；对照确认公共平面RGBA差异为0、透明轮廓未变、关键细节在1×仍可辨识。记录检查过的区域和修整内容，再进入导入阶段。

此流程的完成条件是最终网格中各大平面连续、结构细节可解释且已查看同倍率对照，不是承诺生成工具或某种滤波能自动保证无杂色。以本次发电笼为例，底座由零碎的相近灰色改为连续前面／底边阴影，固定片和两处螺钉单独保留。

## 5. 跑轮案例：采样偏移实测

输入为本次生成的2048×768双图，左半是1024×768；目标64×48。复用当时16色调色板、Alpha<192置透明的导入方法。两轴都以 `16*x + offset`、`16*y + offset` 取点，与offset=8比较：

| 块内取样位置 | 改变的目标像素 | 占64×48画布 |
|---:|---:|---:|
| 0 | 1030 | 33.53% |
| 7 | 392 | 12.76% |
| 8（基线） | 0 | 0% |
| 9 | 349 | 11.36% |
| 12 | 615 | 20.02% |
| 15 | 940 | 30.60% |

**仅把大图采样点在两轴各移动1个源像素，最终约11%～13%的像素就发生改变。** 对严格16倍复制且块原点正确的图，同一16×16块内任选位置应得到完全相同结果。这证明当前大图不能按严格整数放大母版处理。

这里改变的是“采样位置”，不是游戏帧率、清晰度百分比或通用质量分。差异包含颜色与透明度变化；不能据此说整体画质提高/降低了相同百分比。

复现：`tools/Measure-Scaling.ps1`。输入为 `evidence/scaling-source.png`（本次跑轮生成原图的固定副本）；结果在 `evidence/scaling-phase-results.json`，图在 `evidence/scaling-phase-comparison.png`。该实验只用于本次样本，不改变实际资产。

## 6. 细节预算随最终尺寸调整

| 最终画布 | 制作重点 |
|---|---|
| 16×16 | 清楚轮廓＋主要色块；关键标记可为1像素，避免多个竞争焦点 |
| 16×32／32×16 | 沿长轴安排瓶盖/电量条，或鼠头/身体/尾巴；短轴空间最紧张 |
| 32×32 | 建立少量结构分区；同材质相邻区域使用连续色块 |
| 32×48／48×32 | 按方向安排机械上下层或动物轮廓，不能仅交换宽高拉伸图像 |
| 48×48 | 机器可容纳门、按钮与格栅，但重复线条保持原生像素节奏 |
| 64×48 | 保留外壳大色块，改装区增加材质需控制亮边与细节面积 |
| 细长64×16等 | 精确安排功能段；不能根据总像素数推断有足够垂直细节空间 |

这些是制作建议，不是原版统一像素定额。对玻璃、轮辐、网格等重复细节，在1×下逐项检查：线是否连通、间距是否稳定、是否与旁边原版素材同样粗细、是否抢过主体。

## 7. 游戏显示与占格

### PNG、PPU与Canvas

常规Unity UI图像的原生逻辑大小可近似写为：

```text
UI大小 = sprite.rect.size × Canvas.referencePixelsPerUnit / Sprite.pixelsPerUnit
屏幕大小 ≈ UI大小 × Canvas.scaleFactor × 相关父级缩放
```

实际还受布局、旋转、裁切和像素对齐影响，应检查目标代码，不机械套公式。世界SpriteRenderer另受相机投影影响。

本次原版抽样PPU为100、pivot居中。公司MOD的`Goods.HdScale`用 `texture.width/(W*16)`补偿高清宽度，并同步增加PPU；该实现只看宽度。因此任何HD贴图都须额外验证高宽缩放因子相同，否则逻辑高度会错。

例：128×96纹理、目标4×3格、PPU由100提高到200，可保持常规64×48逻辑大小；128×128不能据同一宽度补偿获得正确的4×3比例。PPU修正只调整显示比例，不能把粗糙缩图变为原版像素风。

### Mipmap须按代码路径决定

原版物品图集有10级mip，原版`BuildShapeFromSprite`会读取第4级Alpha（默认gridSize=16）。此处mip不只是远景显示优化，也是占格数据来源之一。

- 保持原版占格推导路径时，确认它需要的mip层存在且正确；不要贸然关mip或改变Alpha。
- 使用公司MOD明确Shape／独立占格路径时，可以维持现有无mip、Point的单图方案，但要验证所有调用不会绕回原版mip推导。
- `SetSprite`与`SetSpriteAndShape`不是一回事；差分换图通常保持既有占格，不能为换图顺手重新自动生成形状。
- 原版图集和自定义单图的设置不可混写成“统一关闭mipmap”。

### 透明、留白与点击

画布范围、Alpha轮廓、库存占格和鼠标命中区域应各自记录。若物品逻辑占据4×3满格，透明角仍可能需要接受拖拽；不要把美术透明度当作占格的唯一依据。检查普通点击、透明位置拖动、旋转及装入容器后的显示。

玻璃覆盖笼内轮子时，通常将轮子与玻璃效果合成在同一不透明主体像素中，仅物体外透明；若给整个玻璃舱直接降Alpha，背景库存格会穿透到轮子，外观可能错误。真实层叠半透明需要单独验证材质和混合顺序。

## 8. 资源占用

未压缩RGBA32基础级理论像素存储（不含对象开销、CPU副本等）：

| 每张纹理 | 单张 | 两张差分 |
|---|---:|---:|
| 64×48 | 12 KiB | 24 KiB |
| 128×96 | 48 KiB | 96 KiB |
| 1024×768 | 3 MiB | 6 MiB |

将1024×768作为运行时图、靠PPU缩回去，相比64×48增加256倍基础像素存储，不保证显示更好。完整mip链通常再增加约1/3；PNG文件大小不等于运行时内存。实际加载格式、可读副本、缓存和纹理生命周期还需代码确认。缓存两张精灵，状态变化时切换，避免每帧LoadImage/重建Sprite。

## 验收表

- [ ] 类别明确；原版参考、目标网格和原生尺寸已确认。
- [ ] PNG宽高符合母版；若有HD倍率，两轴倍率相同且记录PPU。
- [ ] 1×图仍可识别；2×/4×最近邻显示无额外平滑；与原版同倍率对照。
- [ ] 保留区逐像素保持；Alpha低值来源已识别，没有把近透明背景算进材质色数。
- [ ] 没有通过任意大图单点抽样自动宣告通过；缩小后的结构经过原生网格修整。
- [ ] 关键孔洞、格栅、轮圈、灯、动物轮廓在目标尺寸可读；缺失细节有明确简化决定。
- [ ] 颜色预算有参考依据；既比较RGB，也比较亮度层级和色块面积。
- [ ] 顶盖、底座、机壳等大平面已按防杂色步骤逐项检查；保留的孤立像素有明确结构用途，修整记录与1×／4×对照齐全。
- [ ] 差分公共区RGBA差异为0；裁切、pivot、位置与占格一致。
- [ ] NativeSize、Point、PPU、Canvas与mip/占格调用路径已核对。
- [ ] 游戏中对照显示、状态切换、移动/旋转、透明区拖动及读档已观察；未做的明确标记待测。

编译通过只能确认资源引用与代码可构建；未观察游戏画面时，只能报告已部署待测。
