# 深空当铺素材制作规范

## 直接生成精灵（2026-11-13，优先执行）

1. 用户要求精灵时，直接调用图像生成工具生成独立精灵文件。先确定主体、批准参考、视角、目标尺寸、占格及背景，使用严格像素周期模板。默认交付直接生成的精灵，预览、概念图或对照图仅在用户明确要求时制作。
2. 禁止先生成高清预览或合图，再裁切缩小、重采样、限色或脚本重画成精灵。合图获批也不自动授权转换。生成文件按实际输出尺寸原样保存。
3. 分别记录目标尺寸与实际输出尺寸，检查统一像素网格、连续平涂色块、完整轮廓、材质、批准造型和透明度。提示词不作为验收证据，技术检查不替代视觉审核。
4. 输出不符时调整提示重新生成。持续不符时说明具体工具限制，转换或重绘须由用户另行明确授权；不得自行通过缩小补成合格精灵。
5. 状态差分从同一母版派生，检查公共区域和透明轮廓对齐。文件哈希、用户批准、技术验收及接入状态分别记录，被否决版本不得作为替换来源。
6. SCALING.md 的转换步骤仅用于用户明确要求的既有贴图缩放或显示诊断。本文后续历史流程中关于预览、缩小、手绘整理的描述均受本节范围约束。


适用：Probably Stolen 的物品、人物立绘、状态差分及 UI 图标。人物任务先读 [PORTRAITS.md](PORTRAITS.md)，以原版确定显示适配、以撒该确定公司MOD的立绘风格；该文包含人物自己的制作与验收流程。下文的16像素库存网格、物品调色板和占格要求只用于物品，不直接套到人物。宣传图、字体和场景背景另行确定规格。

## 首选生图规范（用户指定，优先采用）

**2026-11-12：物品、机器和布偶生图统一使用 [严格像素周期模板](TASK-TEMPLATE.md#首选生图提示词严格像素周期重点)，取代旧生成提示词骨架。** 核心为同一原点与周期的方形像素、每格单色、平涂无纹理、硬阶梯边缘、默认纯绿 #00FF00 背景（含空隙）。忠实重绘保留参考造型；重新设计使用模板中的替换分支。

用户要求生图时优先按此模板执行；下文按素材选工具、原生尺寸制作与验收的规则用于正式精灵制作、整理和游戏接入，不阻止用户明确要求的图像生成。生成结果需如实说明实际尺寸和网格偏差。用户指定透明时使用模板的透明分支。与旧通用提示要求冲突时，以本节和新模板为准。

## 开始任务

1. 识别交付物：概念预览、原生精灵、状态差分、游戏导入四者分别记录。用户仅要求分析时不修改素材。
2. 选择同用途的原版参考。检查导出的 PNG 和 Sprite 元数据，记录画布、占格、主体包围盒、PPU、pivot、调色板、Alpha；检查来源版本。详细实测见 [REFERENCE.md](REFERENCE.md)。
   制作机器或小型物品时，必须同时阅读 [STYLE-REFERENCE.md](STYLE-REFERENCE.md) 对应类别，并选定具体的结构主参考与材质参考；不能只写“原版像素风”。
3. 先锁定**最终原生尺寸**，再设计细节。库存默认格尺寸在本次代码样本中是 16；以目标游戏版本实际值为准。机器 4×3 格的常规母版为 64×48。UI 图标另查模板，原版有 36×36 等非库存尺寸。
4. 按素材、编辑方式和交付格式选工具。手绘或分层修改可用 Aseprite 或其他像素编辑器，规则化像素和批量差分可用脚本。选定工具后在最终原生网格制作，并保留可编辑源文件。
5. **交付与诊断分开**：最终交付独立原生 PNG；用户要求对照或检查像素时，可生成同倍率原图对照与整数最近邻放大图，标明倍率并单独存入 evidence。诊断图不作为运行时资源，不以缩放或限色自动替代原生设计。缩小路径必须执行 [SCALING.md](SCALING.md) 的防杂色检查。

## 制作约束

- **直接生成精灵图**：用户要求生成精灵时，直接在目标原生像素网格上制作并交付通过验收的独立精灵 PNG，同时保留可编辑源文件；对照图和生成大图不能替代原生交付。
- **原版改装**：以真实提取的原版精灵为底材，锁定保留区域的像素。仅在约定的改装区域编辑；使用图像工具重生成的“相似左半边”不能宣称像素保留。
- **调色板继承**：先复用同材质原版精灵的实际 RGB，再用“深空当铺”目录下的 `Probably-Stolen-Original-Palette-20261111.zip` 查补色。选色用包内 `original-game-all-colors.csv` 或 `.gpl`，同名 PNG 供浏览。全色板来自原版纹理采样，物品色阶以同材质精灵为准。颜色数是预算，原版样本有鼠笼 8 色、灌装机 23 色。
- **像素结构**：保留大面积连续色块，参考原版轮廓线宽，按下文“物品像素绘制规则”处理明暗和结构。细节用有目的的像素表达；不要把量化产生的碎点当金属纹理。检查原生图和像素连接，必要时使用整数最近邻诊断。
- **缩小后防杂色（必检）**：顶盖、底座、机壳等同一材质的大平面，在最终原生尺寸下应保持连续色块和明确的明暗分区。缩小或限色后出现的随机斑块、交错近似色、无用途孤立亮点，必须回到原生网格修整，再检查1×和4×最近邻对照；未清理前不得作为最终精灵导入。灯、铆钉、眼睛等有明确用途的单像素细节保留；不为降低色数而抹掉结构。具体流程见 [SCALING.md 的防杂色步骤](SCALING.md#缩小后的防杂色步骤)。
- **Alpha**：导出参考可能含 1/255、3/255 等低 Alpha，统计时同时报告分布和主体阈值。既有原版数据先保留，不能盲目阈值化。新作硬边精灵通常使用 0/255；玻璃优先用调色板内的色块和反光表达，实际半透明另验证混合效果。
- **状态差分**：从同一母版派生。尺寸、画布原点、pivot、占格及公共区域完全一致；只在声明的变化掩膜内修改。先比较 RGBA，再检查渲染；两次独立生图不视为已经对齐。
- **尺寸与占格分离**：PNG 尺寸、透明区、碰撞/拖拽占格是三个对象。装饰透明区域不能让占用格无法点击；不能靠缩小图片补救面板布局。

## 机器结构与制作顺序

2026-11-13 复核：本次六台生产机器以原版机器净水器 `purifier`（48×64）与 `furnace`（48×48）为视角、材质主参考，具体原图见 [机器复核](MACHINE-AUDIT.md)。`portable_water_purifier` 是便携物品，不能代替机器净水器。其他任务按用途选参考；旧 MOD 卷烟机、分装机及被否定的生成稿不再自动成为结构主参考。

1. 先说明机器的工作过程：输入、处理、输出、动力或控制部件分别在哪里；没有进出料的设备按实际功能描述。
2. 将功能组织为可辨认的部件，明确连接、遮挡、支撑与安装关系。料斗、滚筒、处理腔、管路和底座应有用途；不靠堆按钮、螺丝和格栅代替机械结构。
3. 直接在最终原生尺寸的可编辑母版中完成轮廓和主要色块；检查部件比例、视角、厚度、留白及功能路径，结构成立后再细化。用户要求完全重新设计时，重新组织轮廓、处理腔和进出料布局，不载入旧生成稿或复用旧绘图坐标；全新文件、重跑脚本或换色均不等于重新设计。
4. 按实际原图的材质色组和面积完成基础明暗，再按形体安排局部反光，最后补充有功能的细节。外壳、功能部件和状态区域分层，便于局部修改。
5. 从同一母版派生状态，变化对应实际工作的部件；公共区域逐像素保持。交付原生 PNG、可编辑源文件与检查记录。

验收先确认主要部件各做什么、怎样连接、在原生尺寸下能否分清，再判断材质。结构与材质分别对照实际原图；不以颜色数、工具名称或机械装饰数量代替视觉判断。

## 物品像素绘制规则

以下为2026-11-13复核后的制作约定，适用于物品与机器；具体原图观察不冒充原作者的统一规则。用户当前指定的参考、视角与重绘范围优先，不直接套到人物立绘。

### 光源

- 观察方向与光照分别记录。本次生产机器采用 purifier／furnace 的正前上方浅俯视：主要正面边水平，顶部、倒角和端面提供深度，不旋转成大侧面的三分之二侧视。其他物品按选定原图，不强制全游戏同一投影。
- 上前方受光作为起点，按参考的遮挡和材质调整；不把光照的45°当相机角度，不由受光推导布局必须左右对称。
- 同材质相邻面通常用亮倒角、主体中间色与暗侧缘表达转折；比较时先区分材质、凹腔和遮挡。不能规定所有顶面、前面、脚必须满足同一亮度排序。
- 平面底色保持连续平涂，体积靠结构分面、边缘和倒角表现；金属局部反光按“材质”中的多色高光组织，不铺满平面，不画平滑渐变。

### 凸起

- 朝前凸起：顶面亮、上边缘高光、侧面暗、底面最暗。
- 朝上凸起（如把手）：上边缘亮、侧面暗，接脚处压暗。
- 朝下凸起（如脚）：上边缘暗（与本体相接处）、侧面暗。
- 圆形按钮：上亮下暗。
- 顶面与正面之间：一条亮倒角斜面，倒角下方的正面明显更暗。

### 凹陷

- 内凹：上边缘阴影、下边缘高光，阴影厚度对应凹陷深度。
- 面板（屏幕／灯槽）：近黑底，内含几个亮色像素；较大面板才加上边缘阴影、下边缘高光。
- 缝隙沿用参考的有色暗阶，允许紫暗色、冷灰等跨色相关系；看深度与邻接面，不统一填纯黑。

### 线与轮廓

- 外轮廓和必要的内部舱口、边框、接缝可用原图的深色。按遮挡和结构安排线宽，不把每个零件机械描一圈，也不禁止内部深色。
- 斜线保持与方向一致的台阶节奏，线宽、连通方式由结构决定；1:1、2:1只是示例，不要求全部像素仅角接。
- 圆角、圆柱端面按半径和俯视压缩安排台阶；不套固定数列，不用半透明抗锯齿。
- 文字：少量相连像素，中间断开，示意即可，不求可读。

### 材质

- **按原图组织金属色阶与反光**：以实际原版金属部件为样本，读取高光及邻接暗部的 RGB，记录颜色排列、各段长度、线宽、断开位置和暗色衬托。颜色与明度变化共同表现表面转折和光泽，不简化为统一“本色亮一阶”的线，也不强制每条边包含多色。
- 反光的方向和形状服从部件形体与本节光源；平行断续短条仅在参考支持的部位使用，不给所有表面机械套用45°条纹。亮部沿用参考的有色亮阶，不统一换成纯白。
- 多色高光在原生网格用明确的像素段或色块组织，不做平滑渐变、抗锯齿或随机交错杂色；大平面底色仍保持连续。清杂点时保留有结构依据的多色反光。
- 材质色数仅作预算，金属反光的具体色数与排列以选定原图和目标尺寸为准，不为凑预算删掉必要高光层次；暗部沿用参考材质的色相关系；记录主要色块的面积与邻接位置，不对全机执行统一灰转紫或同色相提亮。

### 尺寸

- 较大区域才画阴影和高光，小件只用本色加 1–2 个亮像素；以最终原生尺寸判断。

## 导入与验收

按 [SCALING.md 的验收表](SCALING.md#验收表) 检查，并记录：

1. 原生 PNG、像素尺寸、颜色数及 Alpha 统计；明确颜色预算和参考。
2. 直接查看原生 PNG 和原版参考，读取像素核对线宽、连接、颜色排列及各项绘制规则；机器另核对功能部件及连接关系，金属另核对多色高光。以1×同倍率对照判断辨识度，必要时用整数最近邻查看连接和颜色分布；尺寸、色数、Alpha合格不能单独判定风格合格。
3. 若有缩小：记录输入/输出尺寸、滤波、采样原点、限色规则，以及缩小后重新修整的内容；逐项记录顶盖、底座、机壳等大平面的防杂色检查结果。采样位置敏感性大时回到原生网格修整。
4. 差分公共区域 RGBA 差异为 0；主体位置和透明轮廓没有意外变化。
5. 游戏代码的 Point、PPU、pivot、图集 rect、Canvas 缩放、占格路径已核对。**原版图集 mipmap 与 MOD 无 mipmap 方案分开判断**，见缩放文档。
6. 用户要求导入时：编译，确认部署目标，备份并校验 DLL；不把编译成功当成画面验收。游戏中的实际尺寸、拖拽、旋转、状态切换和读档由实际观察确认。

交付说明必须区分“已生成”“已完成像素验收”“已编译部署”“已在游戏验证”。记录尚未验证项，不用“16色／64×48／原版风格”替代验证证据。打包与上传仍遵守工作区上级约定。
