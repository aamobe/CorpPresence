# 总框架接入与验收

公司增强使用官方 IMod、Unity Mono 与 Main 显式装配。物品框架是总框架中的内容模块，定义检查、注册生命周期、故障报告和回归都经统一入口；不另建加载器或插件注册中心。

## 完整流程

Main 核心阶段安装身份与补丁 → ResourceBootstrap 按实际资源状态等待 → 资源阶段激活物品目录及业务 → Host 执行运行任务 → SaveSlot/SaveBinding 绑定当前存档 → 公司目录/付款/配送取得物品 → Goods 创建、设备自行加工和恢复 → 停用逆序释放。

Catalog 仅描述物品；ItemIdentity 保持持久身份；ItemRegistry 负责工厂所有权；设备保留库存和加工规则。维护报告读取登记状态，不为了显示定义数量而初始化 Catalog、加载纹理或生成物品。

异常路径以[闭环修复](../changes/organize-internal-lifecycle/closure-fixes.md)为准：通用释放失败隔离该运行期，禁止不安全重启；公司工厂失败在官方占位回退前显式拒绝；内部 Guard 将已捕获异常写入统一报告。失败隔离不等于资源全部回收，也不等于业务自动恢复。

## 模块契约与回归矩阵

新增模块或改动现有模块时，必须覆盖下表对应行，并沿相邻行验证实际调用关系。无需为表格新增基类。

| 系统 | 依赖、入口与所有权 | 状态与恢复 | 自动检查及游戏边界 |
| --- | --- | --- | --- |
| 启动/运行 | Main、RuntimeLifetime；先登记释放再获取；资源就绪后 Continue | 失败逆序回滚；清理失败不阻断其他释放 | RuntimeLifetimeChecks、ExtensionChecks；实际启停仍手测 |
| 资源/表现 | GameResources、Tex、Portraits；借用句柄只清引用，自建 Unity 对象由所属模块释放 | 资源代次、缓存失效和语言切换 | 编译、权限、本地化；图像/字体/占格手测；专用资源检查按改动运行 |
| 物品 | ItemRegistry 在核心阶段订阅、资源阶段 Activate；Goods.Catalog 统一描述 | 固定 ID/旧配对；只迁移到本模块仍持有的有效工厂；失败清理保留所有权供重试 | ItemChecks 链接真实注册器及 RuntimeLifetime；ItemDefinitionChecks 读取真实内容；真实工厂及库存恢复手测 |
| 设备/容器 | 所属 Production 模块的 Shell/Setup/OnNew；公用状态图像辅助 | 首次创建与读档恢复分开；槽位只追加；库存/配方/升级由设备负责 | 定义与身份检查、所属专项；满仓/缺电/缺原料及保存重载手测 |
| 公司/付款/配送 | CatalogEntry → Services.PlaceOrder → Pay → Orders/Crates；不可逆操作前准备 | 限购和订单归当前公司状态；重试只补余量，不整单重发 | PaymentChecks、OrderChecks、RestorationChecks；真实钱包、配送和跨日手测 |
| 存档 | SaveSlot、SaveBinding、StoreSession、CorpState；模块状态归当前会话 | 损坏记录写保护；不靠静态业务变量跨档保存；旧档迁移不得清空内容 | SaveStateChecks、恢复专项；真实 IO、换档、库存和改造手测 |
| 扩展/恶意模式 | ExtensionEvent 三事件租约、Malice 局部准备后提交；其余 Ext 委托保留单槽语义 | 模式开关不等于卸载；释放仅撤回自己仍持有的回调 | ExtensionChecks、生命周期组合；事件不重复与现金/代金券手测 |
| UI/剧情/本地化 | CompanyWindow、Engine/人物、Presentation；UI 门槛与后端提交条件一起核对 | 角色状态进 CorpState；语言稳定键及回退；UI 释放纳入 Main | 本地化、订单专项；对话、解锁、排版与输入屏蔽手测 |
| 诊断/构建 | Maintenance 只读快照；正式版无维护输入；固定模块/阶段故障聚合 | 快照复制值、跨会话失效；未知不伪装成零；故障不反向改变业务 | MaintenanceChecks、构建隔离、正式及维护两份官方扫描、入口拒绝契约 |

## 一次模块接入必须交付什么

1. 写清依赖与核心/资源阶段，列出 Main 装配位置、获取资源与释放动作。
2. 指定固定 owner、持久状态归属及旧档兼容；设备说明 Shell/Setup/OnNew 和恢复各做什么。
3. 若经订单获得，核对显示门槛、后端提交、扣款、限购、配送及重试，不能只证明可生成。
4. 使用既有只读诊断值或固定阶段故障，不为显示状态调用 Get/加载/修复入口。需新增状态时说明含义；计数不能代替安装成功或清理成功。
5. 用真实业务入口测试异常、重复操作及与前后模块连接；明确替身边界。运行统一入口，按改动选择专项。
6. 留下提交、游戏构建、两份 DLL 哈希和结果；未做的真实游戏场景写在交接中。

物品的具体字段、素材和创建步骤见[物品接入](item-extension.md)；报告操作见[内部维护](internal-maintenance.md)。

## 统一验收与完成标准

运行 `tools/Check-Maintenance.ps1`，显式传 GameManaged、Dotnet、Python。当前含 29 步，包括物品结构检查、物品与运行期所有权组合、付款订单存档回归，以及正式/维护两份官方权限扫描；任一步失败均停止。检查入口变动时另跑 Check-MaintenanceContract。

统一入口不等于全部专项或游戏覆盖。涉及加工、种植、养殖、资源等待等行为时，再按对应 tools 说明选择专项。不能因没有引入通用设备模板而补造玩法；也不能因统一检查全绿而跳过真实业务验收。

跨系统游戏场景：

- 主菜单等待资源及进入测试档各请求报告，不能创建存档、物品或改变进度；items 已安装不等于所有工厂均注册成功。
- 现金/代金券分别购买，拒绝不扣、成功扣一次；次日配送，保存重载后余量不重发。
- 普通物品、设备、容器分别保存重载，数量、原料、成品、改造、槽位和占格保持；普通水及原版物品不被迁移。
- 切换测试档不串订单、每日次数、库存或剧情；切换模式不重复订阅。
- 经官方入口停用/重启后无重复日处理和登记；记录官方是否必须重新加载，不宣称未支持的热卸载成功。

开发与自动验收、游戏验收、远端交接、工坊发布四种状态分别记录。本轮结果见[总框架整合证据](../changes/organize-internal-lifecycle/framework-integration-evidence.md)。
