# 容器、箱体与背包

仅非液体容器参考；液体容器见[独立流程](liquid-container.md)。遵循[共用契约](common-contract.md)。

完整现有链：[Crates.CreateShell](../../../src/CorpPresence/Production/Crates.cs)建立12×10内库存→绑定当前StoreSession清理→配送填充→取空后排队清理→RebindLoaded只重新绑定当前档拥有的箱体。背包另见[MangoGift.CreateBackpack](../../../src/CorpPresence/Characters/MangoGift.cs)：原版背包初始化后，仅对芒果仓库物品加所有权例外，不是放开所有嵌套。

字段：外部占格、内部宽高/格数、槽位序列、筛选谓词、容量升级等级、嵌套限制、所有权、可售性、空箱是否销毁。Crates的NOT_FOR_RESALE与IMPORTANT_TAG是运输箱规则，不应默认套给普通储物箱。

| 转换 | 守卫/归属 | 消耗/输出 |
| --- | --- | --- |
| 新建→可装入 | 工厂建立窗口和库存，原版负责物品关系 | 不复制内部物品 |
| 装入/取出 | 原版许可与本物品筛选均通过 | 转移所有权，失败保持原处 |
| 取空→排队清理 | 当前会话、绑定代次、空库存 | 延迟销毁前必须复核，不能跨档执行 |
| 读档→恢复 | 还原内部图后重绑当前会话 | 不按默认容量清空现有内容 |
| 扩容→重载 | 等级持久，尺寸按原始基准重算 | 槽位只追加，不重排已保存角色 |

获取可来自配送或奖励；打开、存取、交易与销毁须保持原版库存归属。反例：复制箱子只复制窗口引用，两箱共享内容；旧档清理队列销毁新档的同名箱子。

[示例](../../../tools/ItemAuthoring/examples/container.json)不会生成容器Shell。代码检查满仓/拒收/嵌套、重复绑定、清理代次、升级幂等；实际新箱体只需装物重载与取空清理。任意多层嵌套或特殊背包槽尚需具体需求核验。
