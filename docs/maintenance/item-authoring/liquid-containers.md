# 液体容器生命周期专题（人工独立开发）

完整原则见[主参考](liquid-systems.md)，本页不生成初始化代码。

| 生命周期 | 路线A已核实事实 | 路线B必须独立确定 |
| --- | --- | --- |
| 工厂创建 | InitLiquidContainerItem会把已注册成分量置零 | 自有容器空状态及默认值，不默认调用原版液体初始化 |
| 首次灌装 | 应与Shell空壳分离，OnNew只在首次创建赋内容 | 由独立组成模型和交互协议负责 |
| 读档 | 工厂之后覆盖保存state；后续修复不能再次清零 | 保存版本、容量/内容恢复顺序和失败保留 |
| 空/满变化 | 原版UpdateContainerGoodType按空满写HOUSEHOLD_GOOD/WATER，可能刷新事件特性 | 自有分类/估值唯一写入者，不借原版标签后再删除WATER |
| 跨系统互倒 | 原版仅理解其自己的能力和成分 | 默认禁止，若确有需求另审显式转换协议 |

字段字典需列容量mL、成分µL或B的自定义单位、温度单位、刻度/过滤能力、空壳价值、鉴定状态、容器外观和库存占格。容积与可放置格数不是一回事。只能初始化自己新建的对象，不改共享定义。

获取、装填、使用、加工、售出和销毁的内容归属必须完整；半失败倾倒不能两边都保留完整数量，恢复失败不能用默认满瓶覆盖保存值。独立开发要设计所有操作的重复调用和中断语义。

反例：读档再次调用初始化导致成分归零；独立酒瓶仍使用LIQUID_CONTAINER_TAG，下一次ItemTags修复重新进入WATER分类。现有银血修复不能被当作新酒瓶隔离方案。

代码核验空/满/溢出、单位换算、读档不补满、交互失败与刷新时序；实际验证代表容器的装填/排空/重载。该清单供独立专案使用，不由工具展开成待实现骨架。
