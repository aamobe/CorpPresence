# 成分与路线专题（人工独立开发）

先阅读[主参考](liquid-systems.md)。本页不提供新配方、代码或工具模板。

路线A接受原版统一水容器的分类与估值关系：Liquid表注册的成分参与WaterHelper总量，water只是其中一种成分；非空容器可能被分类为WATER，即使主要成分并非water。路线B拥有独立组成、名称、品质、交易和持久状态；调酒的多含量配方应按B设计。新增酒标签不能解除原版水回调。

人工字段表需区分成分ID、注册所有权、计量单位、组成量、总容量、实际与表观指标、温度/反应状态和显示文本。原版已核实的currentPart按微升计量，部分容量接口用毫升；不能对B强制套原版标签结构。水纯度、异构蛋白纯度和化学纯度分别命名，不共用含糊的Purity。

状态表需覆盖首次创建、混合、分离、加热/过滤/蒸发（仅实际需要的操作）、反应和销毁；每个变更写清输入、守卫、损耗、刷新和唯一写入者。质量或体积守恒须由反应模型说明，不武断要求所有反应前后等体积。

反例：修改原版water名称为自定义酒名影响全局；把未注册成分标签写进保存对象后以为原版GetTotalVolume会自动计入。既有银血是A，不是B的完整案例。B尚无本项目已验证完整实现，必须明确标记。

独立专案检查注册冲突/撤销所有权、单位换算与取整、边界体积、重复回调、反应状态保存；必要实机由专案选代表样品与原版对照。物品工具只拒绝并链接此页。
