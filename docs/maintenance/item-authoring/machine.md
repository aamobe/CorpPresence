# 生产设备

遵循[共用契约](common-contract.md)，仅需求与检查选择。涉及新液体能力/配方的机器整单拒绝；现有封装机的用水代码只供人工参考，不作为工具输出。

案例：[Canning.Seafood](../../../src/CorpPresence/Production/Canning.Seafood.cs)的BuildSeafoodSealer→RunSealer→SealBatch→[ProductionOutput.TryAddBatch](../../../src/CorpPresence/Production/ProductionOutput.cs)。后者只负责放置，失败可能已有部分产品挂入库存，调用者必须回收本批产品后再决定是否扣料；不能把false解释为“从未改变任何库存”。

字段：输入谓词/数量、输出身份/份数、耗电/启动与每批区别、耗材是否重复使用、模式标签、周期来源、功效模块倍率、槽位角色、开关和状态图、出料空间、已付升级等级。单位必须写清格、件、charge和液体毫升；不以一个含混Count混用。

| 转换 | 守卫/变化 | 消耗/输出 |
| --- | --- | --- |
| 关闭→启动 | 当前模式、能量、原料、空间齐备 | 先准备输出，不先扣全批 |
| 生产→部分/完整放置 | 每件实际附着关系确认 | 以实际完成事实结算或回收本批 |
| 满输出/异常 | 保留可重试状态，归还临时产品 | 不重复扣电、不整单补发 |
| 模式/升级→重载 | 恢复标签与槽位角色 | 不重排旧存档槽、不重复收升级费用 |

原版拥有机器周期和库存；模组拥有配方与自己的模式规则。新建初始化默认模式，读档不重置；迁移限定身份和版本。购买沿原目录，生产成品走普通物品身份，出售/拆卸时保留或明确处理内部内容。

反例：TryAddBatch失败后遗留部分成品但没有扣料，造成复制；按固定槽位1认模块，旧设备布局不同导致读档误修。当前AfterMachineBodyStorage按角色处理特定设备，不能全局覆盖。

[示例](../../../tools/ItemAuthoring/examples/machine.json)。代码检查无料/低电/满输出/部分失败/重复启动/升级恢复，实际新设备只测一轮生产及满输出后恢复和重载。设备行为不由此工具自动实现。
