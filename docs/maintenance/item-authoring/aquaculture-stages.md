# 养殖阶段与水产原料转换专题

依据[原版契约核验](native-contracts.md)，真实案例入口为[银血养殖](../../../src/CorpPresence/Production/SilverBlood.Aquaculture.cs)、[水产验料](../../../src/CorpPresence/Production/Canning.Seafood.cs)。养殖、死亡原料和食品是三个不同开发类别；生成器不会自动实现这些行为。

## 物种与状态归属

FishSpecies 稳定键、物品ID、FISH_SPECIES_TAG 必须对应。银血物种注册先要求 GameResources.Ready，已有同键但不同对象时拒绝；退出只移除自己拥有的注册。不能覆盖其他模组物种。

| 状态 | 数据/单位 | 写入者和边界 |
| --- | --- | --- |
| 阶段与年龄 | FishStage、FISH_AGE_TAG；阶段阈值由物种定义 | 原版 AgeOne，受成长/饥饿门槛影响；不由模组额外按夜增加 |
| 健康/饥饿 | 物种maxHealth/maxHunger对应尺度，非默认百分比 | 原版饲喂、饥荒、水环境和断电处理 |
| 重量/饲料 | 克及kcal，各自单位不可互换 | 原版营养和成长路径 |
| 阶段形状与图像 | stageSprites及阶段占格 | UpdateNameAndSprite；生成器不得用静态形状覆盖成年形态 |
| 用水 | stageWaterNeedMl，毫升 | 原版检查；银血只在自己的过滤边界上施加适应规则 |
| CORP_SB_BLOOD_ML | 血量，毫升 | 模组；不是年龄、重量或原版水容量 |
| CORP_SB_DRY_TAG | 当前环境不足标记 | 银血BeforeTickTank按阶段需求重算 |

## 生命周期与交易路径

注册物种 → BuildCreature 创建壳体并 InitFishItem → SetupCreature 绑定自己的夜间回调 → 原版入缸与TickTank → 阶段成长/移动/死亡 → 宰杀/切片 → 原料验收 → 食品生产/交易。读档恢复必须重新绑定行为，但不能再次初始化健康、年龄、玩家状态。

银血 Nightly 仅在活体、在缸、非干燥、至少成年且健康达到物种上限90%时恢复血量，每次最多+40且不超过容量。原版负责年龄、喂食与成长。断电健康豁免在 AfterTickTank 有限定对象的恢复流程，不得推广到原版鱼。

原版 TickTank 末尾会 TryBreed/WanderStock；具体物种是否满足雌雄、鱼卵、饲喂和空间条件须另核对，不从植物复制基因系统。出缸、成长空间不足、负坐标放置、断电、缺水、死亡必须单列边界。银血 BeforeTankFits 仅在自己的放置上下文内拒绝越界格，让原版继续寻找合法位置，不直接取消整晚结算。

## 活体、死鱼、切片、肉糜、成品

| 输入 | 必须辨别 | 不能混同 |
| --- | --- | --- |
| 活体 | 物种、阶段、健康、活死、缸归属 | 不能因为鱼类标签就用于要求死鱼的配方 |
| 死亡整鱼 | 死亡标记、未切片、物种、阶段、重量 | 当前封装配方只接受亚成年普通罗非鱼，非所有水产通则 |
| 切片 | 切片状态、份数/重量转换 | 不继承整鱼的完整数量与成长状态 |
| 鱼肉糜 | 独立Goods身份、数量、配方来源 | 不按显示名称识别，也不是活体养殖对象 |
| 鱼罐头/蟹味棒 | 输入组合、耗材、产量、品质是否继承 | 不自动带入活体夜间回调或血量状态 |

每个新配方明确：准备输出所需容量、失败时原料保留、可复用耗材与一次性耗材、部分成功结算。涉及新液体配方或液体操作的需求整体退出工具，不仅删除液体字段后继续生成。

## 需求与验证

独立需求表列：物种ID/注册所有权、每阶段阈值与形状、年龄和饲喂单位、成长空间不足、缸容量/供电、繁殖适用性、死亡与原料转换、保存字段、发放和交易资格。无已验证案例的行为写待核验，不制造完整模板。

失败反例一：模组夜间再次加龄，与TickTank双重成长。反例二：按“鱼”名称接收活鱼、错误物种或已切片原料，造成数量/价值不守恒。

代码检查覆盖定向身份过滤、错误阶段/活死/切片拒收、成长空间、失败不扣料及读档恢复不重置。实际新增行为后必要实机为一个跨阶段成长/重载及一个原料转成品流程；本次参考核验没有执行实机，不宣称所有物种的繁殖或交易已通过。
