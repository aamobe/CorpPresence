# 植物收获物与化学原料

遵循[共用契约](common-contract.md)。纯固体收获物可做需求草稿；带新成分的原料完全退出工具，见[液体边界](liquid-systems.md)。

案例：[Perfume.Plants.RegisterAroma](../../../src/CorpPresence/Production/Perfume.Plants.cs)在收获钩子给新产物添加花浆；[Perfume.Chemistry](../../../src/CorpPresence/Production/Perfume.Chemistry.cs)接续化学处理。此链是已有成分系统，不能用普通静态商品模板复制。种子物品数量、花朵件数与内部微升量是三个独立计量轴。

| 字段 | 需要明确的单位与归属 |
| --- | --- |
| 来源 | PlantDefinition与种子ID、收获钩子的执行次数 |
| 固体产量 | 件/堆叠单位，健康公式和取整方向 |
| 基因继承 | 哪些基因只影响本次输出，哪些随产物保存；不得默认复制全部种子状态 |
| 内部成分 | 微升/浓度/化学属性，归独立开发，不进入工具输入 |
| 加工资格 | 精确身份和状态谓词、最低数量、残余物处理 |

状态链：收获守卫通过→准备新产物→只对新增产物施加产量/基因效果→放置成功→交给后续配方→出售/消耗。原版收获时序归原版，模组只拥有自己的输出钩子。新建可赋新产物默认值，重载不可再次执行收获增量，迁移不可重乘基因倍率。

反例：把16mL新增成分误写成16个固体；把potent再次乘到已经含有的全部成分。前者数量不守恒，后者重复放大。

[示例](../../../tools/ItemAuthoring/examples/plant-produce.json)仅声明纯固体来源与品质待办。代码检查来源过滤、数量边界、一次性钩子、加工拒收和保存；实际需求最小实机为收获→加工→重载。涉及成分的实验不由工具执行。
