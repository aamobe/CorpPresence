# 水产加工品与食品

遵循[共用契约](common-contract.md)。FOOD分类、食用能力和生产配方是三件事；工具不自动生成后两项。

案例链：[Canning.Seafood.SeafoodFood](../../../src/CorpPresence/Production/Canning.Seafood.cs)创建独立Shell、设置分类和美术→Setup调用FoodItemHelper.InitFoodItem及罐装/普通食品音效→机器配方输出→原版食用/交易。fish_can与crab_stick不继承活体阶段和夜间成长。

字段：成品稳定ID、每份kcal、isCanned/isMeat、件数/堆叠、基础价、品质继承、音效、原料身份、可复用耗材、每批产量、可腐败性依据。涉及新成分或液体操作的配方退出工具，现有100mL用水规则只是人工参考。

| 转换 | 守卫/状态 | 消耗/输出 |
| --- | --- | --- |
| 准备成品 | 食品身份、热量、标签初始化 | 不提前消耗原料 |
| 放置成功 | 检查实际附着关系 | 才结算本批原料/能量 |
| 食用/出售 | 原版食用对象与顾客规则 | 按原版消耗，不重复销毁 |
| 重载 | 原版恢复状态，恢复必要能力 | 不重算并覆盖已有品质 |

原版拥有食用和交易流程，模组拥有明确配方与自己定义的品质。反例：只加FOOD标签即宣称可吃；把可重复使用的打印耗材每批销毁。新建默认与恢复已有值应分开。

[示例](../../../tools/ItemAuthoring/examples/food.json)。代码检查热量/数量/原料资格、可复用耗材、失败产物回收及无活体回调；实际食品最小实机为生产一批→食用或出售→重载。未验证的腐败机制保持待查。
