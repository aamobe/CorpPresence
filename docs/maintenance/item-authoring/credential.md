# 卡片、凭证、任务物品与奖励

遵循[共用契约](common-contract.md)，只输出待办。唯一性和领取状态不由普通商品生成器决定。

案例一：[Cards.Make/Build/Relabel](../../../src/CorpPresence/Items/Cards.cs)按公司生成/恢复凭证。案例二：[MangoGift.Call/Schedule](../../../src/CorpPresence/Characters/MangoGift.cs)通过当前会话、可写存档和MangoGiftStatus控制礼物发放。自有电话号码遇其他Mod占用时不抢占；界面文案不等于发货成功。

字段：稳定卡ID、公司/剧情绑定、是否可售/转让、每档唯一还是每实例唯一、领取标记、重试剩余量、通知状态、跨档会话、销毁后是否允许补发。状态0/1/2的具体语义必须对应当前实现，不当作所有奖励统一枚举。

| 转换 | 守卫/归属 | 消耗/输出 |
| --- | --- | --- |
| 未领取→待配送 | 当前档可写且身份正确 | 不在绘制UI时发物 |
| 待配送→已完成 | 真实放置与领取门禁成功 | 仅发实际缺失量 |
| 满仓/失败→待重试 | 当前会话仍有效 | 不先标完成、不整单重发 |
| 读档/切档 | 模组持久领取状态，原版恢复物品 | 不把通知队列和工厂默认当领取状态 |

获取沿公司/剧情入口，展示沿文案绑定，交易按明确可售规则，退出按剧情条件。反例：先记已领取后发货失败导致永久丢奖；每次读档发现物品不在手上就再次发奖，玩家出售后可无限领取。

[示例](../../../tools/ItemAuthoring/examples/credential.json)。代码检查不可写档、会话失效、满仓、重复调用及部分发货；实际新奖励最小实机为一次领取、满仓重试和重载不重复。任务进度迁移须独立审阅。
