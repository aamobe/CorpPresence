# 分类参考的共用接入契约

适用证据：发布源码9ce9689及[原版契约记录](native-contracts.md)中的程序集指纹。分类说明是源码核验，不是每个功能的新一轮实机验收。以下内容与每类文档合读，构成完整参考；复杂类别的示例是需求表，不是可运行物品。

## 每项需求必须明确

| 领域 | 必填信息 |
| --- | --- |
| 身份 | GoodsKey、稳定物品ID、创建基底或独立Shell；既有ID不可重用。新身份须人工审阅后才进入发布基线，工具不得改写旧基线 |
| 表现 | 中英名称/描述、稳定键、俄法文或明确英文回退；PNG原生像素、库存格、鼠标区域分别登记；状态图与旋转须逐状态核对 |
| 经济 | 单份数量、堆叠行为、基础价/实际报价、公司/会员门槛、限购周期、禁运属性、获取方式；不可复制第二套扣款/配送逻辑 |
| 状态 | 每字段ID、单位、默认、范围、写入者、保存载体、刷新时机、迁移版本；区分原版状态、模组状态、派生值和可丢弃缓存 |
| 行为 | 输入资格、成功效果、消耗时机、产出、失败保留、重试规则；输出准备完成后再扣料/扣款 |
| 生命周期 | 资源就绪、注册所有权、新建、读档恢复、每夜/交互回调、切档与卸载；重复绑定和双重结算必须有防护 |
| 证据 | 原版与模组方法、游戏程序集指纹、检查命令、仍需游戏确认的场景；无依据的字段不能进入模板 |

## 原版与模组职责

原版负责已核实的保存、目录实例化、库存图和具体系统状态机。模组只负责自己的定义、注册对象、局部规则与修复。借来的纹理/对象只清引用，自己创建的对象负责释放。注册键冲突应拒绝而非覆盖。

新建可以赋默认状态；读档先恢复保存值再绑定行为；迁移必须限定身份和版本、保留玩家改造且二次调用无变化。不能把工厂初始化重新当作读档修复。

获取 → 放置/库存 → 使用或加工 → 出售或消耗 → 读档/卸载，每一步都要说明最终归属。复杂示例六栏requirements分别承载behavior、states、ownership、persistence、failure、verification；具体字段表写在人工设计文档，工具不推导未填写的行为。

## 统一验收边界

普通商品Check复用ItemDefinitionChecks、ItemChecks和LocalizationChecks，并编译生成后的真实DLL；它不确认游戏可用。复杂类别先用对应专项检查中的真实入口，不复制业务实现作为测试替身。没有新游戏行为的工具/文档无需启动游戏；真实物品开发时才做各类列出的最小实机项目。

任何类别包含液体、化学成分、灌装、混合、液体保存或交易请求时，整单转[液体独立开发流程](liquid-systems.md)。禁止把液体部分删掉再生成一个看似普通的半成品。
