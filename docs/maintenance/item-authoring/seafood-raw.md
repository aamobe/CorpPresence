# 死亡水产、整鱼、切片与肉糜

遵循[共用契约](common-contract.md)，阶段转换见[养殖专题](aquaculture-stages.md)。示例仅需求参考，不生成屠宰逻辑。

真实案例链：[Canning.Seafood.IsWholeTilapia](../../../src/CorpPresence/Production/Canning.Seafood.cs)限定IsFish且非群体、FishSpecies.Tilapia、已死亡、Adolescent阶段；后续SealBatch使用整鱼做罐头。注释/描述中的“未切片”不能仅靠名字判断，应结合原版IsFish/切片工厂实际行为核验。另一路fish_mince是独立物品，不是相同原料的显示别名。

字段：物种ID、活死、FishStage、是否整条/切片、数量与重量单位、堆叠与所有权、加工损耗、剩余骨皮去向、腐败是否存在。原版没有明确证据的保鲜期限不得捏造成已有字段。

| 转换 | 守卫/归属 | 消耗/输出 |
| --- | --- | --- |
| 活体→死亡 | 原版死亡处理或限定屠宰动作 | 保留物种/重量；不能直接改名模拟 |
| 整鱼→切片 | 原版或自有明确转换，资格再校验 | 写清份数、克数与副产物守恒 |
| 原料→肉糜/食品 | 配方精确身份与阶段筛选 | 先准备输出，再消费接受的那份原料 |
| 读档 | 原版保存身份状态，模组重绑自己的规则 | 不将死鱼初始化为活体 |

反例：按FOOD或“鱼”字接受活鱼；把一份切片按一整条鱼结算。获取可由屠宰或采购，退出为食品加工、出售或消耗，不能附带活体夜间回调。

[示例](../../../tools/ItemAuthoring/examples/seafood-raw.json)。检查需覆盖物种/阶段/活死/切片的正反例和部分失败不扣整批；实机最小为正确原料接受、错误原料拒绝、加工后重载。
