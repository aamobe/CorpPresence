# 按“一个顶层目录只放一类东西”重整仓库布局

## 背景和问题

公司增强要长期维护，并且是其他模组沿用同一套开发方式的试点。仓库布局因此不只服务于本项目，还要能照搬。重整前有四个问题：

- 根目录混放了面向玩家的游玩流程说明。
- `tools/` 里 12 个脚本和 23 个检查工程在同一层。
- `docs/` 约 490 个文件里有 388 个是美术参考素材和导出工具，不是文档。
- `docs/changes/` 下五个改动已经完成，仍留在进行中的位置。

## 考虑过的选项

- 选项 1：只补说明，不移动文件。
- 选项 2：按总方案已有的目录约定归位，只移动、不改名、不改正文。
- 选项 3：重新设计 `docs/` 的分类（手册、流程、设计、计划、评审等），全部重排。

## 决定

选了选项 2。

选项 3 起初做过一版，执行中发现它和总方案规定的位置冲突：总方案约定了 `docs/specs/`、`docs/decisions/`、`docs/changes/`、`docs/bugs/`、`docs/assessments/`、`docs/源码地图.md`、`tools/checks/`，并要求总方案与 `AGENTS.md` 放在同一目录。布局要给其他模组照搬，就应当跟总方案一致；要改分类应该先改总方案，而不是在一个项目里另起一套。

移动内容：

| 原位置 | 新位置 | 依据 |
| --- | --- | --- |
| `tools/<检查工程>/`（23 个） | `tools/checks/<检查工程>/` | 总方案：能机械判断的检查放 `tools/checks/` |
| `docs/probably-stolen-art/`、`docs/art/README.md` | `art/`、`art/OVERVIEW.md` | 素材和工具不是文档 |
| `公司增强游玩流程.txt` | `share/` | 总方案：对外分享的说明放 `share/` |
| `docs/changes/` 下五个已完成的改动 | `docs/changes/archive/` | 总方案：完成的变更归档 |

没有动的：

- `src/` 的内部目录和命名空间。源码分层留给框架开发计划的阶段二，避免和进行中的源码改动冲突。
- `manifest.xml`、`Localization/`。它们是打包上传的输入。
- `docs/releases/` 下的源码快照清单。里面的路径是发布当时的事实，不改写。
- `docs/maintenance/`、`docs/localization/`、`docs/superpowers/`、`docs/mod-development-guide.md`。总方案没有规定它们的位置，沿用现状。
- 任何文档正文和文件名（`docs/art/README.md` 因为与美术目录自己的 README 重名，改叫 `OVERVIEW.md`，是唯一例外）。

### 后果

- 好：根目录只剩入口文件和随模组发布的内容；`tools/` 一眼能看到全部脚本；`docs/` 只剩文档。
- 好：布局与总方案一致，其他模组可以直接照搬。
- 坏：归档的五个改动目录没有按总方案加日期前缀，保留了原名。
- 坏：检查工程到仓库根多了一层，工程文件里的相对路径从 `../../src` 变成 `../../../src`。
- 坏：外部收藏的旧路径会失效；`docs/releases/` 的历史快照清单里仍是旧路径。
- 坏：进行中的开发分支需要变基一次。全部是重命名加路径修正，Git 能跟随文件。

### 怎么确认

- `tools/Check-Maintenance.ps1` 与 `tools/Check-Portable.ps1` 全部通过。
- `tools/Check-Repository.ps1` 的文档链接检查通过，扫描范围加入了 `art/`。
- 全仓搜索旧路径字符串，除历史快照和一处历史引文外没有残留。
