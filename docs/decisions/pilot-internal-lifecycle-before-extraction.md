# 先验证模块生命周期再抽取共性

状态：拟议 · 2026-11-11

## 背景

已有运行期所有权和事件租约。维护报告能看到三个事件的登记，但模块安装整体与失败阶段仍需从源码追查。两种实际接入分别使用内部事件和原版事件，清理契约可能不同。

## 决定

先验收当前维护能力。用 Malice 验证模块状态、阶段日志和实际安装入口的回归，再由第二模块检验是否存在稳定共性。继续使用显式装配。进入第二期前看第一期定位证据，抽取前看两处共同规则和测试。详见[分期提案](../changes/archive/organize-internal-lifecycle/proposal.md)。

## 影响

增加一期可独立回退的验证工作，并限制每次迁移的调用点。若试点证据不足，保留按需整理；若第二个模块语义不同，保留两处局部实现。第二期结束时据实记录采用或撤回。
