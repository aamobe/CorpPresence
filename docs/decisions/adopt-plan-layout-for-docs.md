# 按总方案的布局整理文档，只归位、不重写

## 背景和问题

仓库根目录新增了 `总方案.md`（开发流程、模板、设计经验和技术资料的详尽版）和按它改写的 `AGENTS.md`。仓库原有一套成形的文档（维护、功能、发布、美术、复盘），要不要、以及在多大程度上按总方案的目录布局重新组织？

## 考虑过的选项

- 选项 1：不动，只在 `AGENTS.md` 里做指路。
- 选项 2：能和总方案的位置一一对应的文档归位，其余保持原样；不改写内容。
- 选项 3：全部按总方案重写，例如把功能文档改写成“需求加场景”的规格格式，补齐所有模板文件。

## 决定

选了选项 2。

- 归位的：源码地图、功能规格（`specs/`）、问题复盘（`retrospective/`）、已完成的实施计划（`changes/archive/`）、三份历史说明（并入 `releases/archive/`）。
- 新增的：章程、决策记录、更新日志、变更目录的说明。它们有现成的真实内容可写。
- 保持原样的：`maintenance/`、`releases/`、`art/`、`probably-stolen-art/`、`localization/`、`mod-development-guide.md`、`tools/`。
- 暂不建的：存档数据模型、日志约定、许可与素材。这三份需要先通读代码才能写准，不能凭印象填；等下次碰到相关改动时再建。

### 后果

- 好：`AGENTS.md` 里每类问题都能指到一个确定的文件；旧文档的内容和措辞没有变。
- 好：所有文档间的链接在移动时自动改写，移动前后失效链接都是 0。
- 坏：外部如果有人收藏了旧路径（例如 `docs/maintenance/retrospective/`），链接会失效。
- 坏：`specs/` 里的文档还是原来的“维护规则”写法，不是总方案附录 B 的格式；两种写法会并存一段时间。

### 怎么确认

对仓库里全部 Markdown 文件的相对链接逐个解析，确认目标存在；搜索旧路径字符串确认没有残留。`tools/Check-Repository.ps1` 也检查文档链接，但它需要 PowerShell 7，这次整理的机器上没有，没有运行。

## 更多信息

总方案自己的说法是“老项目的规格不补课，碰到哪块补哪块”“已有项目沿用原位置即可”。这条决定是在这个前提下取的折中。
