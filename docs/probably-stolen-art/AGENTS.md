# 深空当铺素材制作规范

适用：Probably Stolen 的物品、人物立绘、状态差分及 UI 图标。人物任务先读 [PORTRAITS.md](PORTRAITS.md)，以原版确定显示适配、以撒该确定公司MOD的立绘风格；该文包含人物自己的制作与验收流程。下文的16像素库存网格、物品调色板和占格要求只用于物品，不直接套到人物。宣传图、字体和场景背景另行确定规格。

## 开始任务

1. 识别交付物：概念预览、原生精灵、状态差分、游戏导入四者分别记录。用户仅要求分析时不修改素材。
2. 选择同用途的原版参考。检查导出的 PNG 和 Sprite 元数据，记录画布、占格、主体包围盒、PPU、pivot、调色板、Alpha；检查来源版本。详细实测见 [REFERENCE.md](REFERENCE.md)。
   制作机器或小型物品时，必须同时阅读 [STYLE-REFERENCE.md](STYLE-REFERENCE.md) 对应类别，并选定具体的结构主参考与材质参考；不能只写“原版像素风”。
3. 先锁定**最终原生尺寸**，再设计细节。库存默认格尺寸在本次代码样本中是 16；以目标游戏版本实际值为准。机器 4×3 格的常规母版为 64×48。UI 图标另查模板，原版有 36×36 等非库存尺寸。
4. 按 [SCALING.md](SCALING.md) 决定缩放路径。任何降采样、高清贴图、尺寸异常或游戏中锯齿/杂点问题必须读完整篇，不能只执行“最近邻＋限色”。

## 制作约束

- **直接生成精灵图**：用户要求生成精灵时，直接在目标原生像素网格上制作并交付通过验收的独立精灵 PNG。仅在用户明确要求预览或概念稿时，才可只交预览；放大图、对照图和未通过网格一致性验证的生图大图均不能代替原生精灵。
- **原版改装**：以真实提取的原版精灵为底材，锁定保留区域的像素。仅在约定的改装区域编辑；使用图像工具重生成的“相似左半边”不能宣称像素保留。
- **调色板继承**：先复用同材质参考的实际 RGB 值，再按新增材质增加必要颜色。颜色数是预算，不是风格标准。原版样本有鼠笼 8 色、灌装机 23 色，不能强制所有尺寸统一 16 色。
- **像素结构**：保留大面积连续色块，参考原版轮廓线宽，按下文“物品像素绘制规则”处理明暗和结构。细节用有目的的像素表达；不要把量化产生的碎点当金属纹理。放大预览用最近邻，不增加画面本来没有的细节。
- **缩小后防杂色（必检）**：顶盖、底座、机壳等同一材质的大平面，在最终原生尺寸下应保持连续色块和明确的明暗分区。缩小或限色后出现的随机斑块、交错近似色、无用途孤立亮点，必须回到原生网格修整，再检查1×和4×最近邻对照；未清理前不得作为最终精灵导入。灯、铆钉、眼睛等有明确用途的单像素细节保留；不为降低色数而抹掉结构。具体流程见 [SCALING.md 的防杂色步骤](SCALING.md#缩小后的防杂色步骤)。
- **Alpha**：导出参考可能含 1/255、3/255 等低 Alpha，统计时同时报告分布和主体阈值。既有原版数据先保留，不能盲目阈值化。新作硬边精灵通常使用 0/255；玻璃优先用调色板内的色块和反光表达，实际半透明另验证混合效果。
- **状态差分**：从同一母版派生。尺寸、画布原点、pivot、占格及公共区域完全一致；只在声明的变化掩膜内修改。先比较 RGBA，再检查渲染；两次独立生图不视为已经对齐。
- **尺寸与占格分离**：PNG 尺寸、透明区、碰撞/拖拽占格是三个对象。装饰透明区域不能让占用格无法点击；不能靠缩小图片补救面板布局。

## 物品像素绘制规则

以下为用户确认的制作标准，适用于物品与机器的新绘、重绘及状态差分。与旧制作建议冲突时以本节为准；原版实测资料仍保留为参考，不直接套用到人物立绘。

### 光源

- 光总是从正前上方约 45° 照来，左右对称。
- 明度：**45° 倒角斜面最亮 > 正面、顶面 > 竖直侧面 > 底面与脚（最暗）**。
- 平面一律本色平涂，不画渐变；体积只靠边缘和倒角表现。

### 凸起

- 朝前凸起：顶面亮、上边缘高光、侧面暗、底面最暗。
- 朝上凸起（如把手）：上边缘亮、侧面暗，接脚处压暗。
- 朝下凸起（如脚）：上边缘暗（与本体相接处）、侧面暗。
- 圆形按钮：上亮下暗。
- 顶面与正面之间：一条亮倒角斜面，倒角下方的正面明显更暗。

### 凹陷

- 内凹：上边缘阴影、下边缘高光，阴影厚度对应凹陷深度。
- 面板（屏幕／灯槽）：近黑底，内含几个亮色像素；较大面板才加上边缘阴影、下边缘高光。
- 缝隙：与相邻面同色调的深色线，不用黑。

### 线与轮廓

- 描边：最深的一阶，只画在与透明区域接触的地方，内部结构不描边。
- 斜线：像素只在角上相接，台阶比例固定（1:1、2:1），不乱跳。
- 圆角：1-1-2-3 或 1-1-2-2-3 台阶，不用半透明过渡。
- 文字：少量相连像素，中间断开，示意即可，不求可读。

### 材质

- 光泽面：45° 平行的断续亮短条，用本色亮一阶，不用白。
- 每种材质 3–4 阶；暗部用同色相深色。

### 尺寸

- 较大区域才画阴影和高光，小件只用本色加 1–2 个亮像素；以最终原生尺寸判断。

## 导入与验收

按 [SCALING.md 的验收表](SCALING.md#验收表) 检查，并记录：

1. 原生 PNG、像素尺寸、颜色数及 Alpha 统计；明确颜色预算和参考。
2. 1×原生图、2×或4×最近邻预览、同倍率原版对照。物品逐项核对上文六类绘制规则；只有高清预览不得判定通过。
3. 若有缩小：记录输入/输出尺寸、滤波、采样原点、限色规则，以及缩小后重新修整的内容；逐项记录顶盖、底座、机壳等大平面的防杂色检查结果。采样位置敏感性大时回到原生网格修整。
4. 差分公共区域 RGBA 差异为 0；主体位置和透明轮廓没有意外变化。
5. 游戏代码的 Point、PPU、pivot、图集 rect、Canvas 缩放、占格路径已核对。**原版图集 mipmap 与 MOD 无 mipmap 方案分开判断**，见缩放文档。
6. 用户要求导入时：编译，确认部署目标，备份并校验 DLL；不把编译成功当成画面验收。游戏中的实际尺寸、拖拽、旋转、状态切换和读档由实际观察确认。

交付说明必须区分“已生成”“已完成像素验收”“已编译部署”“已在游戏验证”。记录尚未验证项，不用“16色／64×48／原版风格”替代验证证据。打包与上传仍遵守工作区上级约定。
