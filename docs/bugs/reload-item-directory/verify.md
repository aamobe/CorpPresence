# 重读存档后的公司物品目录验证

2026-11-12。1.2.0 在首次进入店铺时注册了物品。退回主菜单后，原版全局目录仍持有首次注册的托管对象，并拒绝第二个同类型目录。Unity 把场景对象已销毁的托管对象视为 null，导致公司物品可用性检查提前返回。

替身检查模拟首次目录保留、重复目录被拒、Unity 对象与 null 比较为真。旧代码在配送箱、商品和名片创建处失败。修复后工厂可用，卸载也能从保留的托管目录移除自己拥有的工厂。配送检查覆盖实物入箱、柜台放置和待配送数量结算。

框架回归使用正式的配送收货、发卡、绞肉机和物品注册逻辑，替换 Unity 场景、库存与电源。增加重进同档后的实物验证、旧回调隔离，以及成品工厂失效时保留足量原料的检查。

| 场景 | 游戏内操作 | 预期 | 结果 |
| --- | --- | --- | --- |
| 已付款订单 | 使用仍有待配送订单的存档，留出柜台空间。退回主菜单，重进同一档，在订单预定或顺延日接待快递员。开箱核对数量，再重读一次。 | 送到的箱里有实物，待配送数量按实收扣减，无二次扣款或重复发货。 | 待实测 |
| 首次来访发卡 | 使用米洛还未完成首次来访的存档，留出柜台空间。退回主菜单再进档，完成首次来访对话，并再读一次。 | 柜台有一张帕斯泰尔名片，记事簿与电话记录可用，重读后不会重复发卡。 | 待实测 |
| 绞肉机出料 | 在测试存档退回主菜单再进档，给绞肉机装电源并腾空成品槽。分别用足量生肉、合格鱼片和营养果各跑一次，记录各自的成品与余量。 | 肉、鱼和营养果生成对应产物。营养果的剩余热量与实际产量相符。若提示成品尚未就绪，记录所用原料并保留当前日志。 | 据用户反馈，先前已有玩家实机确认绞肉机恢复正常。本次公司物品解码保护的实机覆盖见下表。 |
| 切换存档 | A 档保留已付款的待配送订单，退到主菜单后进入 B 档。检查 B 档的柜台、订单和资金，再回 A 档核对待送明细。 | A 档的待配送状态保留，B 档没有来自 A 档的商品、订单或款项。 | 替身已覆盖旧配送回调，待实测 |

若实机复测失败，立即保留当前 Player.log、版本与触发步骤。仍有待配送的订单可继续按原流程重试。1.2.0 的完整发布文件与哈希留作回退快照。

## 解码就绪与读档完成

原版主菜单选档和退回主菜单后重进同一档，都由 `LoadGameUI` 经主菜单控制器进入 `InventoryScene`。快速读档由第三方 Mod F5ForceSave 1.8.0（工坊项目 3828962908）提供。它设置目标档案后重载同一场景，复用 `EmporiumEntry.Start` 调用 `PlayerStore.LoadGame` 的原版流程。

解码前只检查当前批次实际引用的公司物品。单件创建失败可交由原版生成同 ID 的占位物品。占位、目标库存拒收或容器子槽缺失都会将本次恢复标为不完整，并提醒一次不要覆盖原档。原版保存仍可执行。公司配送、来访和读档后物品修复等到成功重读原档后恢复。

| 场景 | 替身验证 | 游戏内验证 |
| --- | --- | --- |
| 单件工厂失败或原版拒收 | 同库存的其他物品仍恢复。目标库存拒收、子槽缺失及故障件的物品 ID 出现在维护报告，单次读档只提示一次。 | 用原档副本分别复现公司机器工厂失败、目标槽拒收和容器子槽缺失，核对成功重读后配送和名片各落地一次。 |
| 资源延迟或工厂冲突 | 纯原版存档照常读写。公司物品工厂不可用时提示一次，原版解码和保存照常执行。工厂就绪后重试能创建真实物品。 | 分别测试纯原版存档和含公司机器、配送箱的测试档。核对提醒内容与保存可用性。安装 F5ForceSave 时，另测其快捷读档及早报恢复。 |
| 缺文件提前返回 | 有当前店铺时也没有执行公司修复。稍后发出的无关晚期事件不会触发修复，原版继续负责缺文件处理。 | 仅在可丢弃的测试存档上模拟选档后文件失效，确认没有执行公司读档修复。 |
| 成功读档或读档异常 | 正常返回且收到本次晚期事件后，在新会话绑定中各执行一次修复。重复事件不重复修复。晚期事件后原版抛错时也不修复。 | 用同一测试存档连续重读，确认配送箱、药品、仓库占格和定制刀仍正确恢复。 |
