## 根因与裁决

- 第 3 项：已复现 Ask/Fire 输出异常消息、遗漏诊断和后续失败静默。修复为每次记录、日志只含异常类型；诊断与日志互相隔离，返回值不变。
- 第 4 项：报告遗漏 `Schedule` 对每个预约的 try/catch。当前失败保留预约并退避重试，其他预约继续。不能采用 `Ask(..., null)`，因为 null 在这里表示取消，会删除失败预约；保留现有行为。
- 第 5 项：已复现菜单故障在进档时丢失。采用运行期/会话两个有界集合，无存档时产生的故障保留到 Reset；补丁安装等明确运行期事件也进入运行期集合。会话故障仍随换档、字典或资源代次变化清除。只保存不可变字符串和值，不保存存档引用或异常对象。
- 第 6 项：已复现首条故障被噪声挤出。每个集合最多 64 个聚合键，保留最早 16 个及最近 48 个，重复仍聚合计数。最多 128 条，不保证首条就是根因。
- 第 7 项：告警标志确实不会复位；按整个 Mod 启用周期重置三个事件及 Ask/Fire 的日志节流，不清理订阅。原 probe 只停启 Malice，不能代表 Main 的完整停启；新回归覆盖实际运行期重置入口。
- 第 8 项：补丁目标缺失仅写日志。添加可测试的补丁安装记录边界，成功计数、缺失/异常记录；安装异常仍向上传播触发原有回滚，不吞掉失败。
