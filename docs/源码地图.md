# 源码地图

根命名空间为`CorpPresence`。项目使用游戏官方`IMod`接口、Harmony补丁和Unity组件。大量类型通过partial文件按功能拆开，修改前先查同名文件。

展示文本的稳定键接口、渐进迁移和回退规则见[本地化键维护](maintenance/localization-keys.md)。

## 启动与卸载

`Main.Init`注册设置并建立Harmony实例。`OnEnable`经`RuntimeLifetime`取得资源所有权，先装核心身份与补丁，再由`ResourceBootstrap`等待游戏资源就绪。资源阶段注册植物、化学成分、事件和恶意模式，最后创建`Host`处理UI和维护任务。

`OnDisable`按所有权释放回调、事件、资源和对象。启动中途异常必须能够回滚，避免第二次启用时留下重复注册。

## 公司与订货

- [Company.cs](../src/CorpPresence/Companies/Company.cs)：`Tier`是合作/会员档位，`CatalogTier`是经过模式回调后的目录可用档位。
- [CatalogEntry.cs](../src/CorpPresence/Companies/CatalogEntry.cs)：商品、门槛、单价与限购定义。
- [Services.Orders.cs](../src/CorpPresence/Companies/Services.Orders.cs)：购物车校验、扣款前检查、限购记录和订单创建。
- [CompanyVisitors.Deliveries.cs](../src/CorpPresence/Companies/CompanyVisitors.Deliveries.cs)：配送来访。
- [CompanyWindow.Meridian.cs](../src/CorpPresence/UI/CompanyWindow.Meridian.cs)：共用`DrawEquipmentOrder`；其他公司也会调用，并非只有罗森。

正常路径：公司面板 → 目录可用性与报价 → `Services.PlaceOrder`再次检查 → 付款 → 保存订单与额度 → 次日配送。UI解锁不等于后端一定允许付款，两处都要追踪。

恶意模式通过[Malice.Install.cs](../src/CorpPresence/Malice/Malice.Install.cs)安装`Ext`回调。普通公司可被目录申请档位限制；索拉纳以会员档位解锁，不使用目录申请，但订阅到期与剧情暂停仍阻止交易。

## 加工与存档

物品先由`Goods`定义、`ItemRegistry`注册独立身份，生产线按物品ID安装交互和加工逻辑。对旧物品的处理在`LoadedItemRepair`、`ItemIdentity`、`ItemTags`和各线的迁移函数间分工。

`Companies`保存公司状态，`Persistence`绑定当前存档会话。机器额外进度常以物品标签持久化。禁止靠静态变量跨存档保存订单额度、采血次数或配方进度。

## 内部维护与扩展

- [MaintenanceSnapshot](../src/CorpPresence/Maintenance/MaintenanceSnapshot.cs)：只读值对象，包含版本/资源代次、绑定状态、两类写保护、订单/物品条目、缓存计数、故障和三个事件的登记者。
- [MaintenanceDiagnostics](../src/CorpPresence/Maintenance/MaintenanceDiagnostics.cs)：只读采集及跨会话复核，有界故障聚合；不调用加载、写入或修复路径。
- [MaintenanceConsole](../src/CorpPresence/Maintenance/MaintenanceConsole.cs)：仅维护构建的按键入口。正式版保留诊断核心，不含此类型。
- [ExtensionEvent](../src/CorpPresence/Integration/ExtensionEvent.cs)：BeforeSave、DayStart、StateReset 的具名订阅及租约；其余 Ext 字段保持原语义。
- [Malice.Install](../src/CorpPresence/Malice/Malice.Install.cs)：局部准备安装，成功后提交所有权，失败回滚本次租约。
- [Services.Payment](../src/CorpPresence/Companies/Services.Payment.cs)：生产和付款/订单检查共用的 Pay，不导出第三方支付接口。
- [统一检查](../tools/Check-Maintenance.ps1) 与 [维护手册](maintenance/internal-maintenance.md)：明确依赖路径、固定检查列表和证据层级。
