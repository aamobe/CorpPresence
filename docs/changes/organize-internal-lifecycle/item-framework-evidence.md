## 实现

- Goods.Catalog 承接既有基础定义和各产线定义汇总，Goods 保留创建、使用和运行态缓存。ItemIdentity、ItemRegistry、GoodsText 继续承担原有职责。
- DefinitionSet 拒绝定义表内部及跨来源重复；批次冲突先校验、后写入，不保留失败批次的部分条目。所有现有定义采用该入口，未新增持久身份或物品。
- Catalog.TryGetArt 与 TryBatteryState 从原有 Goods 解析代码提取，渲染与离线检查使用同一实现。ArtResource.Name 由 Tex 与工具共享。
- 新增 ItemDefinitionChecks，读取真实 Catalog、身份、文本及资源；名称、必需键、身份创建命名、身份贴图路径、基础/状态图像和公司卡片分别检查。NativeSprite 和 TintedNativeSprite 明确描述原有手册/硬币例外，不将原版回退当成缺自有图像的豁免。

## 失败证据与修正

1. 以原字典覆盖行为运行重复定义测试，先报 `Expected rejection: duplicate definition`；实现带来源批次检查后通过。
2. 字典初始化器的同键覆盖负例先失败，所有生产定义表改用 DefinitionSet 后通过，避免冲突在总汇前已被覆盖。
3. 内容检查的空实现未拒绝缺定义、贴图、名称关联；随后补入真实数据验证。原版手册与染色硬币的无嵌入图像由真实代码核对，并显式标记外观来源。
4. 独立审查发现名称可缺失和 LegacySprite 未关联的漏洞。名称缺失/空白、缺名称绑定及未知贴图键负例先失败，再修正；真实贴图检查直接使用 Catalog.TryGetArt。
5. 首次全套检查在 restoration 停下：旧脚本从 Goods.cs 用正则提取箱子定义，移动定义后生成空清单，8 项失败。已将该既有测试输入更新为 Goods.Definitions.cs，并在未取得箱子时明确失败。该专项仍是文本提取加业务替身，不能冒充真实 Unity 箱子恢复；新增完整内容检查不使用正则复制定义。
