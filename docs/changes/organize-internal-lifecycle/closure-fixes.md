# 框架异常闭环修复

基于 cb0da2e，继续用户要求的框架闭环工作。先复现，再修复，再验证；不改变物品身份、存档字段、设备配方或官方加载方式。

## 设计与裁决

1. 通用释放 Action/IDisposable 无法保证抛错前未产生副作用，不能盲目重放。RuntimeLifetime 和 OwnedCallbacks 完成一次尽力释放，保留失败状态；失败运行期拒绝重新启动，已释放的回调集合拒绝新获取。Malice 清理失败保留状态并拒绝再次安装，不伪装成干净卸载。ItemRegistry 的显式工厂所有权重试仍保留。
2. 公司独立工厂若返回 null，必须在官方创建入口生成 dummy 前明确失败；保留 DirectoryMaster.Item 的所有官方后处理，不直接调用原始工厂替代官方入口。仅约束本模块声明的工厂，原版物品路径不变。
3. Hooks 的 Guard 委托给可测试的内部保护入口，记录固定模块/阶段故障并继续后续操作。RuntimeTask 与内层 Guard 不重复记同一异常；不自动重做可能部分完成的读档修复。

## 验收与限制

失败不覆盖原始异常、不阻断其他释放、不允许在未确认干净的运行期重新安装；正常启停保持幂等。真实游戏的读档、配送、加工和官方停启仍须手测。通用清理失败需停止该运行期并重启游戏处理，自动检查不证明失败资源已回收。
