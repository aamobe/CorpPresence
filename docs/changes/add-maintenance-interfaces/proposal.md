# 内部维护与扩展入口提案

日期：2026-11-11。状态：总方案交付，等待用户设立目标，生产接口尚未实施。用户已确定优先方便自身开发维护，暂不支持第三方扩展。

## 目的与依据

基线为 main 的 `1f33188`、已发布 1.1.0；发布二进制以 [1.1.0 记录](../../releases/1.1.0.md)为准。依据根目录 AGENTS.md，以及总方案第五章第 2～7 步、附 G 的所有权、存档、钱货和性能约束。

上一轮[分期总结](../runtime-performance/checkpoint.md)暴露了三个维护成本：运行状态分散，故障时需要逐层追踪；内部扩展字段缺少可查询的归属；部分支付检查靠临时提取源码方法，难以跨机器复跑。这次围绕这些实际问题设计，不按类数量增加接口。

## 范围

1. 按需读取运行状态、公司数据绑定状态、已登记回调、待配送数量和资源缓存数量。
2. 有界记录近期故障，明确区分拒绝、未就绪、成功和支付结果不确定。
3. 先整理三个真实生命周期事件的注册与撤销，保留现有业务顺序。
4. 把真实付款实现接入仓库内测试，停止为这些场景复制或提取方法正文。
5. 提供统一的本地检查入口和维护说明，每期附总结和证据。

非目标：第三方 SDK、公开类型兼容承诺、插件发现、反射扫描、动态加载、联网服务、远程控制、任意命令执行、自动修档、重发整单、新公司/商品/配方、玩法数值调整、正式玩家维护面板。内容注册框架等出现第二个真实使用场景再设计。既有未闭环的游戏问题继续保留，不借本次重构宣称解决。

## 维护者的使用方式（拟议）

维护构建中，维护者在主菜单或存档内主动请求一次状态报告：能看到版本、资源阶段、存档状态、订单计数、缓存计数和最近故障。未加载公司数据就显示“未加载”，不为查看报告强制加载。报告不包含账号、存档原文或机器路径。

正式构建保留必要的内部状态查询及有界故障记录，调试按键不编入正式 DLL。玩家正常操作和已有日志入口保持原样；不自动导出文件、不新建玩家设置。

## 增量规格

### 新增需求

- **R1 只读快照**：必须只读已有状态。当没有存档、资源未就绪、公司数据未绑定或损坏时，必须返回相应状态；不得创建 PlayerStore、加载/迁移公司数据、补齐公司记录或调用存档写入。
- **R2 快照隔离**：必须返回值和独立只读集合，不暴露游戏对象、委托、可变字典或存档原文。当采集过程中会话变化时，返回“不稳定”并丢弃公司统计；不得拼接两个存档的数据。
- **R3 有界诊断**：必须限制近期记录条数和单条长度。同一故障频繁发生时更新计数，切换存档时清除旧存档业务记录，停用时释放；记录或输出失败不得改变业务返回值。
- **R4 注册归属**：三个生命周期事件必须支持具名注册、独立撤销和重复释放。当安装部分失败时，撤销本次已注册项；不能移除其他拥有者的登记。同一次分发中新增的订阅从下次生效，已撤销但尚未执行的订阅不再执行。
- **R5 事件错误隔离**：一个监听者异常时必须记录归属并继续执行后续监听者；事件按登记顺序执行。这是相对当前多播整体捕获的有意变化，必须单独测试。相同事件的重入分发拒绝并记录，不递归执行。
- **R6 付款语义保持**：正式入口与测试必须调用同一份付款实现。当扩展收费抛异常时仍返回状态不确定，不补扣现金，不自动重试、不宣称已回滚。零费用入口仍须执行既有存档保护。
- **R7 可重复验证**：维护检查必须通过仓库入口执行，使用明确传入的本机依赖；任何子检查失败必须使总入口失败。输出分开标识源码、替身、游戏和发布证据。

### 修改需求

- 生命周期事件由直接修改委托字段转为具名登记；其他业务查询与收费扩展暂时沿用既有调用语义。
- 付款方法可按职责移到独立 partial 文件，调用方签名、本地化键、现金/代金券/期限与订单规则不变。

### 移除需求

- 新检查替代的临时方法提取方式不再作为正式回归入口；保留历史证据，不删除历史记录。
- 三个已迁移事件禁止旧字段赋值和双重分发；其余扩展不得顺带批量重写。

### 维护容量（设计建议，不是游戏数值）

| 项目 | 上限/规则 |
| --- | --- |
| 近期故障 | 64 个聚合键，满后淘汰最旧项 |
| 故障键 | 来源 + 阶段 + 错误代码 + 异常类型 |
| 单条诊断正文 | 最多 4096 字符，禁止保留 Exception 对象 |
| 相同故障计数 | int.MaxValue 饱和，不溢出 |
| 维护按键请求 | 至少间隔 1 秒；只响应按下沿 |
| 采样频率 | 手动请求；不增加逐帧扫描或定时全量检查 |

## 取舍与成本

仅补日志最省代码，但不能解决状态查询和回调归属；全面接口化会扩大付款、存档和生命周期的回归面。本提案选择只读诊断、三个事件和付款测试这三条实际路径。代价是临时存在新旧扩展入口，但边界可列清楚，后续迁移有使用证据再决定。

游戏测试仍由用户手动执行。1.1.0 的暂缓授权是当次发布的记录，不把它扩大为以后所有发布的永久豁免。本轮只请求制定方案，不执行游戏、部署、打包、发布或合并推送。
