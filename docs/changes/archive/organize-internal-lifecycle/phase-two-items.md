# F2 · 第二期：物品接入流程与自动检查

2026-11-11，基线 99719c4。用户明确项目以物品扩展为主，并选择调整第二期。原版顾客/夜间事件试点暂缓；本轮没有修改其代码。

## 目标和边界

让新增物品的身份、注册、创建、旧档识别与检查步骤有统一入口。保留现有 Goods → ItemIdentity → ItemRegistry → 官方目录流程，不增加第二套注册系统，不改已发布 ID、键、槽位、配方或付款。先形成真实入口回归与接入清单，再以证据决定第三期应集中哪一条规则。

第一期与第零期游戏手测仍待完成；按用户要求先执行第二期自动部分，不将自动检查等同游戏通过。

## 本期实现计划

使用 executing-plans 与 test-driven-development；采用仓库轻量任务格式，在本文件记录执行结果。

- [x] I1 原生契约：核对 ModItemDirectory 的 Add/Remove/InitDirectory 与 DirectoryMaster.Item 入口，记录静态结论和替身差异。
- [x] I2 注册器回归：新增 tools/checks/ItemChecks，链接真实 ItemRegistry，替代官方目录、物品及内容工厂。覆盖等待资源后 Activate、重复安装/注册、ID 冲突不覆盖、单项失败继续、目录切换、只移除自有工厂、创建身份校验、旧身份迁移与只读计数。发现失败时先保留失败证据，再最小修正生产入口。
- [x] I3 身份兼容：直接读取本次正式编译 DLL 的真实 ItemIdentity 常量表，维护 99719c4 的已发布身份基线，允许追加、拒绝删除或修改旧身份映射。检查唯一 ID、非空身份及 Goods/Company 二选一；负例验证检查确实拒绝破坏性修改。仅访问字符串记录，不加载游戏或 Goods 初始化。
- [x] I4 接入文档：写明普通物品、机器/容器、状态差分各要定位哪些文件，区分已有本地化/资源检查与尚未覆盖的贴图视觉、占格、机器行为。用已有物品说明，不新造示例物品。
- [x] I5 自动验收：纳入 Check-Maintenance，运行正式/维护构建、所有回归、双版本扫描及检查器失败契约；独立审查，记录可复现命令与待游戏检查。

## 审查重点

不因测试替身的清理/异常行为宣称真实 Unity 通过；未知物品和普通水不得迁移；遇 ID 冲突必须保留别人的工厂；身份基线不能随当前源码自动覆盖；旧目录释放不能删除被别人替换的工厂。若修正注册器，保持官方调用位置和创建时机。

## 未覆盖与后续候选

- 目录替换用例只证明新目录获得登记。当前注册器只持有最近目录，旧目录若仍被外部持有，其工厂回收未由此证明；本期不扩大到多目录所有权重构，后续应结合官方目录重建路径评估。
- 真实 Goods 定义、全部贴图和公司目录的一致性尚未建立全量关联校验；本地化既有检查仍照常执行。
- 游戏手测见 verify.md 的 I-G1/I-G2，旧档、普通水、机器与容器恢复均保留待测。

## 独立审查及修正

独立只读审查提出两项重要的检查器漏洞，已分别按 RED→GREEN 修正：

- 工厂类别检查必须与真实 `entry.Goods == null` 分派一致。新增空字符串/空白的双向负例先失败；修改为严格 null 二选一，并拒绝已填字段为空白后通过。
- 实际 ResolveId 增加未知 ID 配已知贴图、旧 ID 配错误或空贴图的负例。先用按贴图单独识别的错误解析器证明新检查会失败，再实现配对检查；两种错误解析器均被拒绝，真实 90 条身份正负例通过。

最终单项 ItemChecks 为 41 条断言通过，记录于 `artifacts/phase-two/review-green.log`；原 37 条为审查前结果。

Final: minor (deferred)：基线断言固定为 90 条，后续正式发布新增条目并审查追加基线时，还须同步修改来源元数据与数量断言。保留明确快照门槛，避免自动接受未经审查的基线变化。

Final: Ruling：审查未独立重跑的官方 IL 与基线哈希采用本轮主代理读取记录；游戏工厂、旧档、普通水实际行为、容器恢复与旧目录释放保留未验证。代价是引擎特有问题仍可能在手测时发现；本期仅交付开发工具，不据此发布玩法更新。
