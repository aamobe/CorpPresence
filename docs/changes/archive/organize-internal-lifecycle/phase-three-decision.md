# F3 · 第三期决定：保留现有物品接入实现

历史决定：用户随后明确先完成物品框架、再提供物品需求，且依托原框架搭建。本轮继续方案与结果见[物品框架实施](item-framework-evidence.md)；本文保留当时判断，不再作为阻止实施的门槛。

2026-11-11（Asia/Shanghai），源码基线 `a948375`。用户确认本轮暂无新增普通物品或设备，先完成换机复现与交接。本决定沿用总方案允许的“不抽取”路线，不修改生产代码。

## 核对与判断

| 真实入口 | 已有共用部分 | 必须保留的区别 |
| --- | --- | --- |
| Goods 的 stamina | Goods.Def、ItemIdentity、ItemRegistry、Goods.Make、GoodsText | 使用效果落在 Goods 的使用分支，不需要库存页和设备恢复 |
| ProductionWorkBay | Definition 返回 Goods.Def，经 Goods 汇总及统一身份注册 | 自有 Shell、五页库存、允许物品集合、按位置恢复子库存；页面顺序是存档承诺 |
| CargoWarehouse | Definition、Goods 汇总、身份和注册入口 | 自有库存扩容、筛选与恢复规则，不能仅因同为容器就与工作仓统一 |
| candle / candle_lit | 明确身份配对、统一创建入口 | 状态差分不等于独立 Goods 定义；按 GoodsKey 全局唯一或要求所有状态有独立定义会误拒绝现有行为 |

核对依据为 [Goods](../../../../src/CorpPresence/Items/Goods.cs)、[工作仓](../../../../src/CorpPresence/Production/ProductionWorkBay.cs)、[货仓](../../../../src/CorpPresence/Production/CargoWarehouse.cs)及[接入清单](../../../maintenance/item-extension.md)。这是静态调用路径比较，不是新增内容的工时测量或游戏验收。

Goods.Make 在注册器创建后执行 OnNew；Goods.Build 处理定义及 Shell。将普通用品、设备和读档恢复都改为统一初始化回调，会混淆新建和恢复时机。已有共用入口继续复用，不再包一层转发接口。

定义汇总中的字典索引赋值确实可能覆盖同键；本次未确认现有重复键，也未建立合法覆盖与状态变体的完整规则。它保留为后续一致性检查候选，不以“存在索引赋值”认定运行故障，不在本轮改变冲突行为。

## 决定与代价

第三期本轮以保留局部实现的决定交付。现有定义、身份、资源和获取入口仍需人工对照，不能宣称接入步骤减少、全链关联检查完成或新增物品更快。第四期仅收敛已有证据和交接；零、一、二期的游戏验收继续未完成。

重新进入抽取前，需要两类已确认的真实内容任务、相同失败契约与所有权，以及重复维护位置的记录。先选择一个规则，写清文件、合法例外、正负例和回退点；测试通过真实生产入口，不用复制业务逻辑证明自身正确。若两个消费者仍需不同契约，继续保留局部实现。

跨设备结果和剩余验证见[复现与交接](cross-device-handoff.md)。
