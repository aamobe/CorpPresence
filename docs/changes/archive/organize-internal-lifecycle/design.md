# 设计：显式装配与模块生命周期

> 2026-11-11 范围修订：用户确认以物品扩展为主，第二期改为[F2 · 物品接入与自动检查](phase-two-items.md)。下文原版事件第二模块属于此前路线，已暂缓；本期不把 ItemRegistry 的等待目录、激活和实际注册压成单一安装标志。

## 试点选择

- **首选 Malice。** `Main.EnableResources` 已用 `RuntimeLifetime.Own(Malice.Install, Malice.Uninstall)` 接入。模块安装独立，现有三类事件租约、局部回滚及重试测试可作为对照。本期增量是整个模块的只读状态、失败阶段证据和真实调用链覆盖。保留原租约、原发布顺序及其余委托语义。模式开关与 Mod 启停各有独立含义。
- **第二候选 Hooks 的原版事件段。** `Hooks.InstallEvents/UninstallEvents` 管两项 `ModHook` 订阅，已在资源阶段装配。它能验证相同的启停与观测需求是否也出现在原版事件接入。Harmony 补丁仍由 `Main` 的 Harmony owner 统一撤销。两类事件的订阅机制保持各自契约。
- **暂缓 ItemRegistry。** 其安装、等待目录、激活和替换目录分属不同阶段，卸载依赖工厂引用相等检查。已有计数；若过早统一，会把“已监听目录”和“目录已有可用工厂”混成一个状态。物品解码、迁移和注册归属需要单独评审。

## 调用链与观测

`IMod.OnEnable → RuntimeLifetime.Start → ResourceBootstrap → RuntimeLifetime.Continue → Main.EnableResources → 模块 Install`。保留 `OnDisable → RuntimeLifetime.Stop → 逆序释放`。模块内的回调归各自安装者。资源未就绪沿用 `GameResources.Poll`，清理只触及实际拥有的订阅或对象。临时宿主继续由 Main 停用并销毁。

第一期从 Malice 已有成功标志提供只读值，供快照输出固定模块名和「安装已提交」状态。三个事件的 owner 仍从 `ExtensionEvent.Owners` 查询。该值描述安装提交事实；清理异常发生后应保留失败信息，不能仅凭标志推断全部资源已回收。采集失败沿用快照的 Unstable 语义。未安装时采集不能触发安装、读档或访问会创建玩家的入口。格式化与业务保持单向依赖。

在现有启动失败日志路径附上固定模块名及安装阶段，先保留原始异常语义再执行现有回滚。局部清理失败在其现有告警路径记录固定模块名及释放阶段，后续释放仍继续。引擎回滚后无维护热键宿主，故障定位依靠日志。快照不保留异常对象、原始日志或游戏对象引用；不新增玩家提示、轮询或永久错误列表。回调注册失败仍导致原资源阶段失败，禁止把半安装报告成成功或自动重试整段初始化。

## 接口门槛

优先内部只读属性、普通方法和直接调用。只有两个真实模块已验证同一生命周期语义、相同错误边界与相同所有权，才抽取一处共用逻辑。仅出现一个可替换的外部依赖、且必须在正式适配器与可执行故障替身之间切换时，才考虑最窄的内部参数或接口。测试通过同一生产入口；禁止复制业务实现作为替身。若删掉共用层只是恢复两次短小显式调用，保留各模块实现。具体类型签名由已验证的第二调用方确定。

每期对比维护者定位一次注入故障需要查看的文件与日志步骤，记录一次停用、重启后的实际 owner 数、两种构建的输出差异、接入点和依赖数量。试点最低收益是凭一条启动日志定位模块及阶段，凭一次维护报告确认成功启动的模块状态，并用测试证明异常路径没有重复登记。没有数据时保留为空。

## 九项门禁

| 项目 | 设计约束 |
| --- | --- |
| 所有权 | Main 管运行期顺序，模块管自己的租约，保留先登记释放、逆序清理和重复停用行为。 |
| 原版边界 | 原版事件、Harmony owner、过滤和时序沿用既有实现。 |
| 存档 | 零持久化差异，旧档用同样的键、ID 和槽位读取，不引入迁移。 |
| 不可逆 | 不进入支付、发货和对象销毁的业务路径，付款未知结果不补扣。 |
| 门槛一致 | 原 UI、模式开关、业务门槛沿用现有实现。 |
| 简单性 | 显式接入、逐模块迁移，抽取可取消。 |
| 权限 | 无新增运行时依赖、权限或加载机制；正式与维护版都用官方扫描。 |
| 性能 | 状态只在启停更新，报告按需读取固定数量的值，不增加周期工作。 |
| 授权 | 只借鉴原则，不复制第三方实现、素材或测试代码。 |

待核对：实测游戏构建的官方启停顺序和可操作入口，以[原版契约](../add-maintenance-interfaces/native-contracts.md)及当期游戏版本为准。第二候选若无法在保持原生事件时序的前提下构造可靠故障替身，停在第一期并记录理由。
