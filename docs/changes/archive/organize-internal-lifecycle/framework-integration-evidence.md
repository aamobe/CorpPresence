## 技术裁决

- 使用本机官方 DirectoryMaster.GetFactory 核对最终工厂引用，不仅检查 ID 存在；既有 DirectoryMaster.Item 仍负责官方创建后处理。
- 全调用点审查发现 ItemRegistry.Create 也是原版模板、血袋、c4 和 galaxy_blend 的既有入口。先以四个原版 ID 复现严格所有权误拒绝，再将所有权约束限定于 ItemIdentity 声明的独立身份，保留其他物品原有目录路径。
- 物品模块沿用 Main 的核心订阅与资源阶段激活；报告 installed 表示订阅已安装，不承诺资源就绪或全部工厂注册。
- 清理单项失败继续后续清理，保留仍属于自己的失败条目及目录供重试。重新安装前清理遗留，不能成功时明确拒绝；替换目录前同样清理旧所有权。不会删除已被其他工厂替换的条目。
- 内容检查读取真实 Shell/Crate/LegacyId，验证普通物品具备创建基底；不调用 Unity 工厂，不承诺原版基底实际存在或其行为正确。
- 统一检查直接纳入维护版权限扫描，避免总框架交接遗漏第二份产物。
- 独立审查发现全局工厂遮蔽后重复通知会遗忘本地清理所有权，补失败断言后修正：本地持有与全局有效分开，遮蔽只拒绝创建，不遗忘自己的释放责任。
- 官方 Directory<T>.Create 会重写返回物品 ID，DirectoryMaster.Item 在空工厂结果时可生成 dummy。ItemChecks 的错误身份替身只验证注册器防御分支，不证明真实 Unity 工厂产物正确；本轮工厂引用核对也不替代实际创建验收。
