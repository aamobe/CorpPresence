# 内部生命周期增量规格

## 新增需求

- L1：维护报告必须能区分试点模块是否完成安装。**当**模块安装成功并采集报告，**则**显示该模块已安装；**当**未安装或已完成停用，**则**只读采集不会触发安装或加载存档。
- L2：启动失败必须可归到固定模块及阶段。**当**模块安装部分成功后抛错，**则**保留启动失败事实，撤回本次拥有的登记；**当**释放抛错，**则**留下清理失败证据并继续后续释放。
- L3：重复启停必须保持登记稳定。**当**停用两次后重新启用，**则**试点模块只登记一次且其他监听者仍存在；**当**仅切换恶意模式，**则**不得将该开关当作模块停用。
- L4：维护观察必须兼容既有玩法。**当**读取旧档、开店、保存或提交订单，**则**行为与同输入下的基线一致；**当**使用正式版按维护组合键，**则**不出现维护入口。
- L5（原版事件试点暂缓，条件项）：第二模块接入必须保持原版事件次序和现有故障隔离。**当**只释放本模块订阅，**则**同原版事件上的其他订阅继续执行。

## 修改需求

2026-11-12 评审修复补充：启动回滚保留运行期诊断至下一次启用；会话故障仍按换档清除。运行期/会话分别有界并保留早期及最近故障；Ask/Fire 的失败每次记录，文字告警按启用周期节流；补丁目标缺失及安装异常进入运行期故障，安装异常保持向上传播。验证与裁决见[评审修复](../../../../bugs/framework-review/assessment.md)。

维护报告在原有事件登记之外增加试点模块安装状态，原有条目及业务规则继续适用。

## 移除需求

无。

## 第二期物品接入补充

- I1：注册器检查执行真实生产入口；资源未就绪不建物品，ID 冲突保留外部工厂，重复通知不重复注册，停用不删除被外部替换的工厂。
- I2：已发布身份及旧映射以固定基线核对；新增允许，删除、修改、重复 ID 和歧义旧映射应使自动检查失败。
- I3：旧身份仅在目标可用且准确匹配时迁移；未知/原版物品不收养；错误身份临时产物只在未放入库存且尚未销毁时回收。
- I4：接入清单区分普通物品、设备、容器和差分；自动检查明确真实实现与替身边界，不宣称所有贴图、机器和旧档已通过游戏验收。
