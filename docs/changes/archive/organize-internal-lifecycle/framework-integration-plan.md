# 总框架整合实施计划

2026-11-11。用户要求将物品框架融入总框架并继续完成总框架。沿用已确认的内部框架总方案及物品设计，在当前工作分支执行；不新建加载器、插件协议或设备基类。采用 writing-plans 明确任务，executing-plans 顺序实施。

## 目标与约束

让物品模块与既有启动/释放、只读诊断、构建验证、模块交接形成同一条维护路径。保持官方 IMod、Unity Mono、netstandard2.1、零权限及已发布身份/槽位/价格/配方。此次开发与自动验收完成不代表游戏验收或发布完成。

设计依据：[总方案](master-plan.md)、[物品范围](item-framework-design.md)。本轮具体技术裁决：保留 Main 显式装配；复用 MaintenanceModuleState 和故障聚合，不引入模块注册中心；各设备保留业务实现。全系统范围通过统一模块契约和跨模块回归矩阵收敛，不以重写所有业务为完成标准。

## 任务

- [x] T1 注册所有权：在真实 ItemRegistry 的 ItemChecks 中先复现冲突工厂创建/迁移、注册后替换、清理失败。创建及迁移只能使用仍属于本模块的目标；清理单项失败继续释放其他条目。保留其他工厂，不修改身份基线。
- [x] T2 内容完整性：CompiledContent 从真实描述读取 Shell/Crate 与身份 LegacyId；无独立壳体的普通物品必须有非空基底。补缺失/空白拒绝及独立壳体合法负例/正例。
- [x] T3 总框架接入：物品安装状态、清理失败与固定阶段故障进入 Maintenance；只读报告不初始化 Goods/Catalog。ItemChecks 链接真实 RuntimeLifetime，覆盖等待资源、激活、回滚、重复停用和重启。统一入口同时扫描正式及维护版，补入口失败契约回归。
- [x] T4 收敛：新增覆盖全部系统的模块接入/回归矩阵，更新总方案、任务、维护导航和物品接入；执行统一检查及独立审查，记录产物身份与待手测。远端交接与游戏验收分别登记。

## 评审重点

冲突工厂绝不成为迁移目标；释放失败不遮蔽后续释放；状态查询不创建游戏对象；合法 Shell/Crate 不因没有 LegacyId 误报；诊断失败不影响业务；不把专项替身与真实游戏行为等同。

## 进度与裁决

起点：7a4a808，工作区干净且与 origin/main 一致。T1 产生只读状态与所有权判断，T3 消费这些状态；T2 独立，T4 汇总全部证据。游戏验证继续由用户执行；不启动、部署、打包或上传。远端发布授权不推定延续为此次新改动的推送授权。

最终：T1–T4 本地开发与自动验收完成，29 步通过、61 条物品/生命周期断言和 35 条定义断言通过；独立评审与两次定向复核完成。详见[整合证据](framework-integration-evidence.md)。远端交接与真实游戏验收待完成。
