# 第一轮运行性能验证

目标游戏为 Steam 构建 `26525552`。对照组为改动前的本地工作区构建，实验组为同一工作区移除反应釜就绪检查的成品 ID 拼接后的构建。两组使用同一份存档副本、相同设置和 Mod 列表，每次只加载一份公司增强。

| 场景 | 已验证到 | 游戏里怎么看 | 预期看到 | 结果 | 日期 |
| --- | --- | --- | --- | --- | --- |
| 稳定就绪的反应釜 | Release 编译及回调替身 | 闭店，给反应釜装足电量和至少 30 mL 异构体溶液。关掉所有面板，让同一批机器保持就绪，预热 30 秒后记录 60 秒。随后分别测试断电、恢复供电和出料格满。 | 就绪、断电和满格时的贴图与基线一致。检查加工前后产物档位、数量及溶液扣量。 | 待测 | |
| 控制器目录与结账 | 源码追踪 | 用物品较多的同一份存档，先关面板采样 60 秒，再打开博士私人目录采样 60 秒。依次检查控制器在嵌套库存、拖拽中、配送箱、待配送订单和彻底移除时的目录。 | 有实物或待配送时停售，彻底移除后允许补购。结账前的实物复核仍生效。 | 待测 | |

每个连续采样场景分别记录全帧耗时 P95/P99（毫秒）。若已有可用的进程内采样或调用探针，同时记录公司增强耗时和 `MachineAppearance.Tick`、`ControllerAvailable`、`Portraits.Tick` 的调用及耗时，并对实际库存遍历、`MachineAppearance.CanFit` 创建的样品和立绘纹理创建计数。若工具只提供帧耗时，保留原始记录，并把内部指标留空。反应釜替身结果只覆盖就绪回调的托管分配。
