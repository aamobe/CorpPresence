## 银血反应釜

满输出诊断直接提取当前 ProductFor 和 React，游戏库存、原料和供电接口采用替身。旧代码在输出拒收时调用扣电一次、溶液不变。将首次扣电移到产物预放成功之后，缺电则回收预放产物，满输出同场景改为零扣电。

本地 artifacts/reactor-output-check/Run.ps1 的五场景复测通过。

| 场景 | 产物 | 剩余溶液 | 扣电调用 |
| --- | --- | --- | --- |
| 输出满 | 0 | 100 mL | 0 |
| 正常一次 | 1 | 70 mL | 1 |
| 三批次 | 3 | 10 mL | 1 |
| 三批次但仅一格空间 | 1 | 70 mL | 1 |
| 缺电 | 0 | 100 mL | 1 次尝试，返回失败 |

该测试纯度固定为 100%，产物销毁由替身模拟。扣电或液体接口自身抛异常的资源回收、真实堆叠与读档未覆盖。最近正式构建零警告、零错误。

后续补充供电异常注入，发现移动扣电时点后的实现会在供电抛异常时遗留一份预放产物，溶液仍为 100 mL。增加放置与供电阶段的 finally 清理后，相同异常结果为零产物、100 mL；前述五场景继续通过，正式构建零警告、零错误。供电替身在实际扣费前抛异常；接口已扣费再抛异常及液体扣量中途失败仍未覆盖。

游戏手测顺序为满输出保持一晚，腾出一格加工，再移除电源检查。核对产物数量、溶液扣量、电量和状态贴图。养殖和香水机器待继续检查。

## 锻造与烟草包装

锻造和包装同样改为首件预放成功后才尝试本轮扣电；放置或供电失败时通过 finally 回收未提交产物。两个本地诊断分别提取当前 Smelt 和 Pack，满输出、三批正常、仅一格空间、供电失败四场景均通过。满输出不尝试扣电，原料不变；部分成功仅消费成功产物对应原料。包装另核对标签耐久，只按成功包装数扣除。正式构建零警告、零错误。

这仍是库存与供电替身证据，不能代替真实堆叠、扣费后抛异常及原料扣除中途失败的验证。游戏中分别塞满输出过夜、腾出一格过夜、取走电源过夜，核对锭料或散烟、电量、产物和标签耐久。

本地 artifacts/blood-record-check 从当前 Perfume.Blood.cs 提取 ReadDraws，直接链接真实 SaveSlot，替代 PlayerStore 和日期接口。22 项断言通过：无存档拒绝、新记录为零、同日 0 至 3 次、前日记录归零、未来记录拒绝且保留、六种非法记录禁止覆盖、换存档不继承坏数据保护及重复读取共享次数。
