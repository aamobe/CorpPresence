# 勾兑酒工艺方案稿

独立讨论稿，定稿后并入《工艺线扩充方案》。玩家用独立的勾兑瓶配液，压榨机供应风味液。酒瓶放进调和机后，点击「调和」，即时根据瓶内真实成分得到不同酒体。

## 玩家操作

1. **萃取。** 将指定风味原料放进压榨机，点击「萃取」，即时得到固体残渣和由风味物质、水、杂质组成的液体。原料、收率和能耗待定。普通风味可先验证原版的 `wine_extract` 能否作为可测成分。梦尘路线使用原版成品梦尘药品作为原料，待验证其溶入容器后的成分识别。
2. **配液。** 用 750 毫升勾兑瓶装入水、基酒和风味液。瓶容量 750 毫升，草案暂按总液量达到 720 毫升即可调和。原版努特加整瓶倒出 750 毫升，酒精占 45%，建议先倒进化学容器，再按量分入酒瓶。加入的每种原料都按真实成分计算，例如基酒自带的水也进入总水量。
3. **检测。** 玩家用原版化学检测仪检查酒精、水、风味和杂质。调和机可提示容量不足或液体无法读取。成品判定可先通过调和结果反馈，是否提前显示预测酒体留待讨论。
4. **点击调和。** 把达到最低液量的勾兑瓶放进调和机，点击「调和」即时处理一瓶。成功时消耗输入瓶和瓶内液体并生成一件成品。设备电耗、解锁、价格和供货公司待定。

## 调和机瓶槽显示

正面预留一个空的竖向瓶槽，底图保持空槽。放入勾兑瓶时，在槽内按原版酒瓶贴图的比例绘制瓶身，瓶底对齐槽底。取出瓶子或调和成功消耗瓶子后，恢复空槽。显示从真实输入槽读取，读档后也按槽内容刷新。电池和成品使用各自的库存槽，不占正面瓶槽的可见位置。接入前需用原版酒瓶图核对槽位的锚点、缩放和遮挡顺序。

空机贴图为 48×48 像素（3×3 格），使用 art/wine-blender.png。原版酒瓶精灵实测 16×64 像素，在机内按 50% 显示为 8×32。槽口内框 10×34，左上坐标 (10, 8)，瓶身左右各留 1 像素，上方预留 2 像素。瓶身绘制在 x=11–18、y=10–41，底部与槽底对齐。输入瓶已装好勾兑液，正面瓶槽用于放置和显示酒瓶。坐标以贴图左上为原点，范围含端点。

## 四类组分与成品判定

### 压榨机设计

![压榨机空机贴图](art/fruit-press.png)

空机贴图为 48×48 像素，占 3×3 格。

采用独立压榨机，设原料槽、电池槽、接液容器槽和残渣槽。玩家放入原料及可拆卸液体容器，点击「萃取」即时处理一份原料。每次同时生成一份固体残渣，并将由**风味物质、水和杂质**组成的混合液直接写入接液容器。水和杂质随风味液一起倒入勾兑瓶，按真实组分参与配比和成品判定。

每种萃取配方分别定义原料 ID、风味组分 ID 与体积、水量、杂质组分 ID 与体积、残渣数量和耗电。首轮建议用一颗原版荧光莓验证整条路线。保留原先 50 毫升试算，调整为 **10 毫升风味物质 + 38 毫升水 + 2 毫升杂质**，另出 **1 块荧光果渣砖**，暂按 **2 电**。这些是讨论值。荧光果渣砖是横向 2×1 格的压制饲料，带卡路里，可用于喂食。建议暂按每块 60 kcal 试算。旧版 WineDirectory 将普通荧光莓初始化为 150 kcal，此处的 60 kcal 是待平衡的方案值。实现时走原版 CALORIE_VALUE_TAG，参考 MachineFeedDispenser.TryBlendItem，按非肉食物进入普通饲料储量。实机核对哪些养殖对象会消耗这类饲料。果渣砖不进入压榨机。普通风味先验证原版 wine_extract。梦尘酒使用原版化学成品梦尘。

原版 MachineBlender 提供原料、接液容器和按键布局参考。压榨机单独实现双产出结算。按键前核对原料、供电、接液容器余量及残渣槽能否接收。剩余容量小于整批液量、残渣槽满或缺电时，整批不启动。首版建议接液槽只收空容器或同配方萃取液。成功后一次提交液体、残渣、耗电和原料消耗。发生异常时核对并撤回本批已放置的产物及已扣资源，避免只出液或只出残渣。

验收先做一次正常萃取，核对液体总体积、三类组分和残渣数量。再分别模拟只剩 49 毫升接液空间、残渣槽满和缺电，确认失败时原料和电量保留。最后用检测仪读出组分，并按量转移到勾兑瓶核对比例。

### 酒体分类

四类占比按实际液体总体积算，总和为 100%。内部沿用原版的微升整数，显示时才四舍五入。水、酒精和风味成分各有独立 ID 或 ID 集合。杂质由配方明确列出的杂质组分汇总。未知组分建议先拒绝结算，并提示玩家倒出重配。梦尘活性组分和其他特殊标志物计入风味总量，再分别检查各自的浓度。同一组分只归一类，避免重复计量。

配方先写瓶内实际组分，再按原料检测值倒推投料。**酒精 + 水 + 风味物质 + 杂质 = 实际总液量**。草案暂将 720 毫升理解为装瓶所需的最低总液量，上限为 750 毫升。水是补足液量的主体，无独立的配方比例窗口。基酒、萃取液、补水是投料来源，每种原料带入的组分要拆开累加。水只统计原版的水组分，原料自带的杂质计入杂质项。

| 酒体 | 建议判定 |
|---|---|
| 劣酒 | 有最低酒精含量，且没有禁止组分，但酒精、风味或杂质未达到其他酒体规格。允许低价出售，作为一次配比失败的结果。 |
| 风味酒 | 酒精与普通风味落在配方窗口内，杂质不超过该酒体上限。 |
| 梦尘酒 | 含指定的梦尘标志组分，而且它的单独浓度、酒精和杂质都符合要求。普通风味总量达标无法替代梦尘组分。 |
| 特殊酒体 | 草案先设浓莓烈酒和双萃梦酒，分别靠较高酒精与莓味、以及莓味与梦菇的组合识别。 |
| 拒绝处理 | 液量不足、基本成分不成立、含禁止或未知组分、输入不是勾兑瓶，或成品没有可用位置。输入瓶和液体留在原位。 |

建议先做拒绝检查，再按梦尘和特殊酒体的配方匹配，最后判定普通风味酒和劣酒。特殊组分同时命中两种酒体时，首版建议提示配方冲突，避免靠隐含顺序决定产物。若酒液含梦尘组分但配比失败，建议拒绝处理并允许调整，避免退成普通酒时丢失特殊性质。

### 第一版酒体配方范围

各百分比按瓶内实际总液量计算。以下酒精、莓味和杂质范围是讨论值。水补到最低装瓶液量即可。

| 酒体 | 酒精 | 莓味 | 梦尘 | 杂质上限 |
|---|---:|---:|---|---:|
| 劣酒 | 至少 6% | 无最低值 | 无 | 1.33% |
| 风味酒 | 11%–13% | 1.07%–1.60% | 无 | 0.53% |
| 浓莓烈酒 | 22%–26% | 2.27%–3.07% | 无 | 0.80% |
| 梦尘酒 | 15%–17% | 无 | 6%–12%（含两端） | 0.67%（待实测） |
| 双萃梦酒 | 13%–15% | 1.07%–1.60% | 6%–12%（含两端） | 0.67%（待实测） |

劣酒只在未命中其他酒体且没有梦尘或禁止组分时兜底。含梦尘却未达目标酒体规格时保留输入瓶，允许重调。

原版梦尘是药品和违禁品，物品 ID 为 dream_dust。旧版 MedsItemDirectory 将其注册为可溶化学物品，ChemFinisherRecipe 以 dream_cap_extract 作为有效组分。草案暂按成酒中的梦尘有效组分占比判定。原版梦尘溶解后是否需要额外追踪原料来源，以及具体采用有效组分还是整份药品折算值，待定。

含梦尘的成酒统一为违禁品。梦尘酒和双萃梦酒的梦尘占比必须在 6%–12%（含两端）。含梦尘但超出此范围时不出酒，保留原瓶供玩家调整。

## 原版与 MOD 代码标注

- **勾兑瓶。** 注册独立 MOD 物品 ID，外观复用原版酒瓶图集 Items/items_winemaking 的 wine_bottle 精灵及占格。容器行为参考 FoodItemDirectory.BottledWater，通过 WaterHelper.InitLiquidContainerItem 初始化为 750 毫升，沿用装液、倒液和比例转移。勾兑瓶不调用 WineHelper.InitWineBottle，也不注册原版发酵状态、按钮或夜间回调。调和机按勾兑瓶 ID 接收。实机核对原版液体容器的液面渲染能否搭配酒瓶图集，以及化学容器和勾兑瓶之间的分量倒液。
- **混液与风味。** 沿用 `WaterHelper.GetLiquidParts`、比例分液及现有化学容器数据。`Liquid.cs` 已定义 `wine_extract` 与 `dream_cap_extract`。先验证检测显示和原版反应，再决定复用哪些组分。压榨机负责从原料制得液体，调和机负责根据比例分类。
- **即时结算。** 参考 CorpPresence 0.9.5 的绞肉机按键入口和 `ProductionOutput`。读取实际液体并确定酒体，确认成品可放置后再提交。异常时核对输入瓶和输出的实际状态，避免同一瓶被重复结算。
- **成品和贴牌。** 新酒使用各自物品 ID，实际酒体与假标签独立记录。贴牌仍是后续可选销售玩法，可参考原版 `LabelerUIManager` 的 `fakeCondition`。先验收配液、分类和出货，再验证验货和销售机制。

代码依据为本地旧版正式版解包的 `WineHelper.cs`、`WaterHelper.cs`、`Liquid.cs` 和 `LabelerUIManager.cs`，以及 `CorpPresence-main.zip` 中的 0.9.5 源码。

## 下一轮要定

先确认最低液量口径和梦尘比例分母。再核对实际原料浓度能否覆盖配方窗口。

实机验收至少覆盖一瓶劣酒、一瓶风味酒、一瓶梦尘酒，外加配比踩线、禁止组分、满成品槽、原版发酵酒瓶和标准水瓶拒收和插瓶后的存读档。
