# 章程

本项目不可违反的原则。每个改动在设计时都要对一遍（做法见根目录 `总方案.md` 第五章“第 3 步”的门禁）。要改这份章程，先在 [决策记录](decisions/README.md) 里写明原因。

## 通用原则

1. **所有权**：物品、状态、资源、回调都要说得清归谁；谁创建谁释放，借来的图集、字体只清引用，不销毁。
2. **事实优先**：成功以可观察的事实为准，不以函数正常返回为准。
3. **不可逆操作**：扣款、销毁、发货之前，校验和准备全部完成；部分成功后按实际完成量记账，重试只补余量。
4. **原版边界**：原版已经负责的流程不重复接管；公共补丁必须带本模组的身份过滤。
5. **存档承诺**：写进存档的物品 ID、状态键、库存槽顺序不改，槽位只追加；迁移可重复执行，并保留玩家自己的改造；不为“修复”清档、重置进度或整单补发。
6. **验证分层**：读源码、静态检查、编译、替身测试、游戏实测、发布核验分开记录，没做的层明说。
7. **发布可追溯**：发布物要能对应到确定的提交、文件哈希和资源；不靠目录名或版本号判断内容。

## 本项目特有的边界

1. **普通水保持原版**：普通水的灌装、倒装、纯度、鉴定、分类、容器估值和原版顾客收货沿用游戏原版。不为公司配方给普通容器加公司身份，不安装覆盖所有液体的估值或接收补丁。细则见 [兼容边界与回归](maintenance/compatibility-and-regressions.md)。
2. **不自行启动游戏**：自动化工具和助手只做编译与静态检查；游戏内验证由人来做，并在报告里写清哪些没实测。
3. **发布和打包要明确授权**：日常修复只改源码、编译、验证；上传授权只用于指定的发布目标，不顺带修改页面介绍和标题。
4. **零权限**：清单保持 `<Capabilities />`。新功能优先用官方受限接口；发布前用官方扫描器确认权限、拒绝项和待生效警告均为零。
5. **素材先过规范**：制作、修改、缩放或导入素材前先读 [美术规范](../art/AGENTS.md)；缩小后的物品图必须完成防杂色检查。
6. **公开仓库不放私有内容**：游戏程序集、反编译代码、凭证、登录缓存、存档、完整个人日志、本机绝对路径都不提交。
7. **撤回的方案不复活**：复用旧方案前先查 [问题复盘](retrospective/README.md)，确认它没有被撤回（例如生产异常的持久锁机方案）。

## 来源

通用原则来自 40 个历史问题的复盘；项目边界来自此前的仓库维护约定和兼容文档。
